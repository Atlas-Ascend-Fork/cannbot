# 工作流图实时预览

把工作流 YAML 解析成一张**纵向分层的节点图**，节点卡片只放摘要，点击后在右侧面板看完整的
task YAML（节点提示词）。文件一改，页面自动重新解析刷新，不需要重启服务。

## 启动

```bash
./run.sh                 # 默认解析 cannbot-dsl/workflows/cannbot-dsl/op-dev.yaml
./run.sh --open          # 启动后自动打开浏览器
./run.sh --port 9000     # 换端口（默认 8765，被占用时自动往后顺延）
./run.sh --host 0.0.0.0  # 允许其他机器访问
./run.sh --workflow /path/to/other-workflow.yaml
```

依赖只有 PyYAML；`run.sh` 会自动挑一个带 PyYAML 的解释器（本机为 `python3.12`）。
也可以直接 `python3.12 server.py`。

## 页面

- **纵向分层**：每行是一层（层号 = 该节点所有依赖层号 +1），节点卡片按依赖顺序自上而下排列，
  层间用箭头连边；同一层的节点左右并排。
- **入线/出线错开**：同一个节点上，多条入线沿卡片顶边等距落点，多条出线沿底边等距起点
  （按对端节点的左右位置排序；只有一条边时仍走正中，贴得近就几乎走直线），箭头不会并成一条。
  落点与卡片左右边缘至少留 40px，卡片过窄时自动收窄。
- **整体缩放**：标题栏的 `－ 100% ＋` 可缩放整张图（25% ~ 300%，档位固定），点中间的百分比回到
  100%；也支持 `Ctrl/⌘ + 滚轮`。缩放以画布中心为锚点，滚动位置不会跳；缩放只改可视比例，
  连边仍按未缩放坐标计算，因此任何比例下都不会压到节点。窗口变宽变窄或打开详情面板时会按当前
  比例重新铺排。
- **全正交走线（横向/纵向 + 圆角）**：一条边从源节点底边出发、落到目标节点顶边，中间只做
  水平/垂直移动，拐角 7px 圆角，没有 S 形飞线。起始点落在朝向目标的那一侧半区（入线落在
  线实际来的那一侧），偏移量随两端横向距离收缩，所以连线只会朝目标方向偏移，不会反向绕行。
- **连边不压节点**：相邻层之间只在行间空隙里横向错位一次；跨多层的长边先落到源行下方空隙，
  再按走向绕到卡片区左侧或右侧的专用泳道（同侧泳道只在纵向区间不重叠时才复用，多条长边按
  泳道序号贴内/外圈，彼此不交叉），最后从目标行上方空隙插回节点顶部。连线既不会穿过卡片，
  也不会被卡片遮挡。
- **空隙内每条线独占一条横向通道**：行间距按最挤的空隙自动放宽；同一个空隙里的横向走线各占
  一条通道（不重叠），并按“压住别人最少”穷举出交叉最少的先后顺序，把十字交叉压到最低
  （本工作流 21 条边只剩 1 处无法避免的十字交叉，没有叠在一起的线）。
- **共线重叠会兜底消除**：同一空隙里若两段竖线落点太近且纵向相交，会把其中一段留在本侧落点
  范围内横向让开，保证“线叠在一起”不会发生。
- **回滚边画成紫色虚线**：`rollback_to` 边与依赖边共用一套拓扑/泳道/通道机制，走线方向取镜像——
  从来源卡**顶边**出线、沿侧翼泳道向上、从目标卡**底边**入线（箭头朝上），与依赖边的“底出顶进”
  在视觉上完全分开。源节点卡片同时保留 `回滚→ xxx` 徽标，悬停/选中时回滚边加粗、目标节点加紫色
  虚线边框。
- **节点卡片只放摘要**：节点 id、类型、执行/验收角色、重试次数、`on_exhaust`、`rollback_to`、
  `depends_on`，以及提示词各字段的条目数（如 `目标 1 · 执行方法 3 · 交付件 2`）。卡片高度统一，
  图始终紧凑。
- **右侧详情面板**：点击节点后，完整提示词（`goal` / `approach` / `procedure` / `acceptance` /
  `out_of_scope` 等按字段分节）连同层级、执行/验收角色、重试与耗尽策略、回滚目标、提示词文件路径
  都在右侧面板里展示；再点一次同一节点、点「关闭」或按 `Esc` 收起。面板里的依赖/被依赖项是
  可点击的标签，点一下就跳到对应节点并滚动到可见位置。面板打开时图会自动重新排布宽度；拖动面板
  左缘的手柄可在 320px ~ 窗口 80% 之间自由调宽，宽度在面板重新打开后保持，拖动过程中连边实时重绘。
- **展开子图**：点击子图节点，在详情面板点「展开子图」，同一画布显示子节点、依赖箭头和紫色回滚边，
  继续使用原有缩放、布局及节点详情。顶部显示图来源并提供「返回主图 / 返回上级」，返回时保留上级的
  节点选择、缩放和滚动位置。真实子图文件优先于规划预览；规划节点不表示实际运行节点或执行状态。
  子节点的引用提示词或组装后的内联提示词均可查看，子图内提示词只读，不扩大原有编辑 API 的允许范围。
- **字段中英对照与可见性徽标**：面板里每个字段同时显示中文名与原 YAML 字段名（如 `目标 goal`），
  并按 harness 可见性标注：`执行方法 approach` 仅执行者可见（蓝色）、`验收方法 procedure` 仅验收者
  可见（紫色），其余字段双方可见；卡片上的字段计数徽标用相同底色区分这两类受限字段，悬停可见
  原字段名与可见性说明。
- **面板内编辑提示词**：详情面板的「编辑」把节点的 `title`、`goal`、`approach`、`procedure`、
  `acceptance`、`out_of_scope` 以 YAML 源码形式整字段编辑（每行一个 `- ` 条目），写回原 task YAML，
  字段名与 YAML 键一一对应。编辑框是代码编辑器风格：等宽字体、行号槽、光标所在行高亮（行号同步标蓝），
  初始高度自动匹配内容行数，仍可从右下角手动拖大（拖大后自适应停用）。保存时逐行校验 `- ` 前缀，
  缺前缀的行会按字段名+行号报错；`procedure` 清空即移除该可选键，其余字段至少保留一条。保存前校验
  文件 mtime+size，外部已修改时拒绝覆盖并提示重新打开；只能写当前工作流节点实际引用的提示词文件
  （子图内的引用或内联提示词不在可编辑范围）。保存后由热更新自动重新解析；编辑中的面板
  不会被热更新覆盖，按 `Esc` 先退出编辑再关闭面板。
- **热更新**：页面用 SSE 监听工作流文件、子图及预览模板、被引用的 task YAML 和 tasks 目录，任何变更（含新增、
  删除文件）都会触发重新解析，右下角提示变更的文件，滚动位置与当前选中的节点/面板内容保持同步
  （选中的节点被删掉时面板自动关闭）。
- **异常可见**：YAML 语法错误、依赖不存在的节点、重复 id、依赖环、提示词文件缺失都会在页面上
  以横幅或角标标出；解析失败时保留上一次成功的图。

## 接口

| 路径 | 说明 |
| --- | --- |
| `/` | 页面 |
| `/api/graph` | 每次请求都重新读盘解析，返回图的 JSON（不缓存） |
| `/api/events` | SSE：`ready` / `change`（含变更文件列表）/ 心跳 |
| `/api/health` | 存活与当前变更版本号 |
| `/api/save-prompt` | POST：把面板编辑的字段写回 task YAML；body 为 `{path, base_mtime_ns, base_size, fields}`，`fields` 只接受 `title`/`goal`/`approach`/`procedure`/`acceptance`/`out_of_scope`；目标必须是当前工作流节点引用的提示词文件，mtime/size 不一致返回 409 |

## 解析约定

- 节点引用：优先取 `yaml`，其次 `yaml_file` / `task` / `file` / `template`；相对路径先按工作流
  所在目录解析，再依次按上层目录（技能根目录）解析，取第一个实际存在的文件。
- `task_type: subgraph` 的节点按子图处理：存在的 `file` 使用同一解析器递归构建子图，按其真实
  `nodes`、`depends_on`、`rollback_to` 显示结构；引用循环或超过 12 层时显示解析警告。
- 对运行时才生成的子图，可以在工作流旁放同名的 `<工作流名>.graph-preview.yaml`，以
  `subgraphs.<节点 id>.stages` 描述阶段，并补充 `nodes`（与工作流节点格式一致）或 `workflow_file`
  （引用现有固定子图模板，优先于 `nodes`）。路径按预览文件所在目录及其上层目录解析。`title`、
  `summary`、`note` 描述图及其限制。只有 `stages` 的旧预览继续显示文字说明。
  这份文件只用于预览，不传给 harness；实际子图文件出现后优先显示真实结构，真实文件解析失败时
  显示错误，不以规划图替代。热更新时保留所在子图视图；子图被删除且没有规划结构时返回最近有效的上级。
- 节点提示词 = task YAML 中除调度字段（`task_type` / `depends_on` / `executor` / `verifier` /
  `max_retries` / `on_exhaust` / `rollback_to` / `yaml` 等）以外的全部字段，新增字段会自动出现在
  卡片里，不需要改代码。

## 验证

```bash
python3 -m unittest discover -s tools/workflow-graph -p test_server.py -v
```

覆盖真实/规划优先级、依赖及回滚、内联提示词、模板与子节点文件监听、只读边界、循环引用及旧预览兼容。
