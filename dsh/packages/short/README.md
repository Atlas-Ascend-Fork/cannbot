# CANNBot DSH

`cannbot-dsh@1.0.0-alpha.1` 是 `@cannbot-plugin/cannbot-dsh@1.0.0-alpha.1` 的短包名入口，安装在原版 DSH 中，不修改核心。

在 **插件 → 添加插件** 中输入 `cannbot-dsh@1.0.0-alpha.1`。新版本受安装源同步及发布时间观察期影响时，请明确指定版本号。
Linux 也可执行：

```sh
dsh plugin --profile web add cannbot-dsh@1.0.0-alpha.1
dsh web
```

安装时通过标准 npm 依赖一次装齐 3 个默认工作流包，目前加载 53 个 Skills；依赖下载失败会让安装阶段报错。首次启用等待本地资源准备完成，不会在后台补装子包。每个 `@cannbot-plugin/workflow-<ID>` 可独立更新和回退，无需升级主程序。目录包 `@cannbot-plugin/workflow-catalog` 用于发现新工作流。

启用后从左侧“CANNBot工作台”进入：沿用当前对话的工作区并展示真实路径，支持分类、搜索及圆形勾选工作流。选择卡片后聚焦输入框，不覆盖已有内容；点击“开始”后按实际进展显示准备状态并进入 DSH 原生对话。准备失败保留输入和文件，可展开原因并重试。工作流更新及日志统一在插件详情中管理。

插件详情提供逐项更新、回退、检查版本和更新全部。回退版本会固定，主动更新该项即可恢复跟随最新版。主程序自己的“检查更新”和一键升级保留。

选择工作目录和工作流时，Host 自动调用包内保留的上游 DSH 安装器准备该工作区；相同工作区和包版本不重复初始化。依赖仓库仍按上游声明获取，某些工作流首次准备需要 Git、网络及其运行条件。输入框不出现 `/工作流名称`，发送时在后台应用工作流。

首次下载需要网络；已安装工作流可离线加载。支持 Windows 桌面与 Linux Web，Node.js >=24.9，DSH >=0.1.1-rc.1 <0.3.0；图形管理依赖对应官方接口。界面开关默认开启，关闭后保留工作流能力。
