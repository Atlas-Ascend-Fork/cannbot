# kb 治理 — 引用、续写与申诉

`references/kb/` 是按板卡组织的事实库：一条主张一个条目，出处先于知识，适用范围不超过证据，
每条自带推翻条件与验证分层。规章正文见 `RULES.md` 与 `form/`，本文件是操作流程。

## 1. 引用

- 格式 `[950:NNNN]` / `[910:NNNN]`，并注明该条目当前分层：`verified`（写明板卡）、`corroborated`、`harvested`、`overturned`。
- `harvested` 表示"从文档或代码收集、尚未上板验证"——可以引用，但引用处必须让读者看见这个状态。
- 只在条目确实是当前判断的依据时引用；不为格式凑引用。条目文件名即主张本身，`ls entries/` 可当索引读。
- 两册事实互不通用：910 的结论不能引到 950 的判断里，反之亦然（RULES.md 第 1 条）。同一事实两册都要，就各自独立建立。

## 2. 新建条目

1. 从 `form/ENTRY_TEMPLATE.md` 起稿；一个文件只放一条主张，文件名 = 编号-主张的小写连字符缩写。
2. 条目头部字段与七个小节由 `form/ENTRY_TEMPLATE.md` 定义，照模板填；其中必须自己想清楚的是四件事：**主张**（一句话，可检验）、**出处**（命令、代码路径、文档章节——先于主张写）、
   **适用范围**（板卡 token 具体到 SKU；范围一个字都不得超过证据实际覆盖的）、**推翻条件**（什么观测会证明本条错）。
3. 初始分层按证据定：仅文档或代码来源 = `harvested`；有独立来源的旁证 = `corroborated`（同一仓库或同一 SDK 发行的两个文件算一个来源，互相印证不算旁证，见 RULES.md 第 3 条）；在具名板卡上实测复现 = `verified`，并在 `BOARD:` 写明板卡。
   分层是诚实声明，不是质量分；宁可低标，不可虚标。
4. 编号取该册下一个空位，不重用已推翻条目的编号。

## 3. 晋升分层

- `harvested` → `corroborated`：补一条独立来源的旁证，写进条目出处栏。
- → `verified`：在 `BOARD:` 具名的板卡上实测复现，记录命令与读数（或指向可复核的运行记录）。
- 晋升只改分层栏和追加证据，不改写原主张；若实测结果与主张不符，走第 4 节，不做"顺手修正"。

## 4. 申诉与推翻

- 认为某条目错误或范围过宽：在该条目文件末尾追加 `## APPEAL` 段——申诉理由、反证（命令/数据/文档）、
  建议处置（缩范围 / 改分层 / 推翻）。申诉不删除、不改写原文。
- 反证成立后：条目分层改 `overturned`，原文全文保留，顶部注明推翻日期、反证摘要与接替条目编号（如有）。
  被推翻的条目留在册中——它记录的是"这个说法为什么错",和正确条目同样有用。
- 缩范围、改措辞或按新证据更正结论：修改在条目内进行，保留被取代的原文、注明日期与依据（RULES.md 第 9 条）；结论变了就同时更新文件名与 `INDEX.md`。证据链（`SOURCE:`）永不删除。
- 谁来裁决：申诉与推翻按本仓通行的评审流程处理——提 issue 或 PR，由该目录的维护者判定；本文件只规定证据与记录的形式，不设独立裁决人。

## 5. 目录

- `book-910/entries/`（910B2 → 910C）、`book-950/entries/`（950PR / 950DT）——条目本体；
- `form/`——ENTRY_TEMPLATE.md、STRATA.md（分层定义）、CONVENTIONS.md（命名与语言约定）；
- `RULES.md`——高于本文件的规章，冲突时以它为准；
- `tools/`——形式检查脚本（`check_entries.sh`），新增或修改条目后运行；
- `harvest/`——条目 `SOURCE:` 链引用的原始材料与矛盾清单；
- `INDEX.md`（每册一份）——编号、分层与主张一句话，用于检索。
