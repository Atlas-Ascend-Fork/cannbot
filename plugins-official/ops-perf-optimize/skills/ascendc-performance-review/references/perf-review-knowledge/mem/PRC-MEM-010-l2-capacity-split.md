# PRC-MEM-010：超 L2 容量数据分片

## 知识点

L2 Cache 读写带宽远高于 GM（官方示例约 7TB/s vs 1.6TB/s）。算子单轮触碰的数据总量（输入+输出）超过 L2 容量时，重复访问的数据在两次触碰之间已被逐出，第二次读直击 GM，带宽瓶颈放大数倍。Tiling 层把超大数据均等切成多个片段、每片（含该片的输入与输出）控制在 L2 容量内、逐片迭代完成，可让片内的重复访问命中 L2——官方示例中每核 GM 读取从 4 次降为 2 次（另 2 次命中 L2）。关键前提是存在重复访问：多核共读同一份数据（广播型输入）或多轮迭代重读，才有命中可言。

## 错误写法

```cpp
// 反例（依官方文档 10_0036 示例重构）：全量数据一轮扫完，
// 工作集 = 输入+输出 远超 L2 容量，共享输入每核都从 GM 重新读
for (int64_t i = 0; i < totalTiles; i++) {   // totalTiles 覆盖全部 GM 数据
    ProcessTile(i);                          // 工作集不设上限
}
```

## 正确写法

```cpp
// 正例（依官方文档 10_0036 示例重构）：外层按 L2 容量分段，段内多核/多轮
// 复用的数据保持 L2 常驻，段间顺序推进
int64_t sliceLen = l2Capacity / bytesPerUnit;         // 单片工作集 <= L2 容量
for (int64_t s = 0; s < CeilDiv(total, sliceLen); s++) {
    for (int64_t i = tileBegin(s); i < tileEnd(s); i++) {
        ProcessTile(i);                                // 片内重复访问命中 L2
    }
}
```

## 识别方法

在被检视源码/tiling 中看：

1. 估算单轮工作集：全部输入+输出张量的字节数（代入典型 shape），超过目标平台 L2 容量为候选。
2. 确认重复访问存在：同一 GM 区域被多核共读（如权重/gamma 广播给所有核）、或算法多 pass 重读同一输入。无重复访问的纯流式一遍扫（每字节只读写一次）不命中——L2 救不了一次性访问。
3. 看 tiling 是否已有 L2 分片维度（外层 slice 循环/分段字段）；没有且满足 1、2，命中。

误报边界：一次性流式访问不报（无命中可言）；工作集本就小于 L2 的不报；容量数字必须按目标平台实际值代入（官方示例 192MB 不可照搬；**dav-3510 用 128 MiB**，来源见 PRC-ARCH-002），检视报告中注明所用容量来源；分片引入的额外调度与边界处理在片数很多时有成本，收益估算应扣除。

## 证据要求

finding 必须给出：

- 工作集估算表（各张量 shape×dtype 合计）与所用 L2 容量数值及其来源；
- 重复访问的代码证据：共读同一 GM 区域的多核偏移表达式，或多 pass 重读的循环结构（文件:行号与摘录）；
- tiling 中无分片维度的确认（相关字段/循环缺失）。
