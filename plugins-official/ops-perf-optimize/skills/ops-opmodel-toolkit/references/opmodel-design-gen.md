# 设计文档生成

解释框架行为时按需查[框架参考](framework/index.md)；性能表的范围与资格见
[评估报告格式](perf-eval/output-format.md)。

用于将实际模型与仿真/搜索结果整理为 `DESIGN.md`。先识别入口和候选身份，再按
[设计模板](../assets/templates/design.md)组织内容；只请求文档时不自动启动新搜索或设备实验。

## 读取已有产物

| 资料 | 提取内容 |
| --- | --- |
| 固定定义、case、有效 params | 数学语义、shape、dtype、阶段、tile 与成本 |
| assignment 与 result | 真实任务分配、scope、总体周期、检查状态、产物路径 |
| ranked.yaml / RANKED.txt / search.json | 候选排名、有效参数、淘汰及覆盖；按实际入口选择 |
| operator 与 buffers | slots、每 slot 字节、存活关系与容量 |
| trace 与统计 | 计算/搬运、忙碌/等待、完整时间范围 |
| 已有设备记录 | 实现版本、数值结果、计时边界与实测收益 |

某个文件缺失时先核对执行入口，不能认定仿真失败。排名报告里的配置片段不能代替
候选的完整定义；搜索第一名也不能自动称为已验收赢家。

## 生成内容

1. 写清算子语义、接口、完整 case、硬件/成本和模型版本；列出本轮交付范围。
2. 从当前 DAG 生成数据通路，按需用[数据流图](dag-dataflow-graph.md)，保留
   GM workspace 与直接片上交接的差异，勿套用其他算子的模板图。
3. 列 tiling、阶段、slots、分核和实际搜索范围；说明候选选择依据及未覆盖维度。
4. 按有效 shape、dtype、slots 和生命周期计算 buffer 占用。区分名义总分配与
   峰值存活，来源不够时写未确认，不能让空表表示容量已通过。
5. 列基线/候选完整 case 周期和同口径收益。局部 DAG 排名另列；物理 CSV 的
   服务周期不能相加充当墙钟时间，`sum(pipe busy)` 也不是总体耗时。
6. 分别列结构、资源、数值、后端、设备验证状态；引用实际证据，未执行写未执行。

## 交付

写入用户指定目录的 `DESIGN.md`，已有文档按用户修改范围更新。包含模型/配置/结果
路径与复现命令，保持命令使用用户模型及安装 wheel。仅有软件示例或合成成本时，
明确其范围；不补写不存在的设备收益、校准资格或全局最优结论。
