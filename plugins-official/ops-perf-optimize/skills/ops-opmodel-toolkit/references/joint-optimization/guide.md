# 算子方案设计与联合优化

目标是得到满足原正确性契约、在声明范围内稳定更快的算子实现。使用模型时，再按需要提高其对未拟合候选的预测和选优能力。模型辅助表达、检查与筛选方案，真实实现的精度和同口径设备实测决定是否采用。分别报告实现收益及实际开展的模型工作。

## 按问题选择方案搜索与实现实验

- **从语义自主提出实现族。** 有算子实现时保留生产对照，区分数学约束与已有实现选择；尚未实现时从公式、接口和数值标准建立独立参考与可运行起点，需要建模时走[公式到模型](tool-routing.md#从公式建立模型)。按已有证据报告收益；没有生产基线时说明比较范围。
- **opmodel 方案搜索可选，适用时推荐优先使用。** 切分与流水存在多个合法选择、模型可表达其差异且成本有效时，优先用内置搜索器缩小空间；明确的实现瓶颈、模型无法表达的差异或已有误排序反例，可直接进行算子侧实验。记录本轮选择及具体理由，不把建模或搜索设为所有实现的前置条件；用户明确要求搜索时遵循其范围。
- **流水优化推荐联合搜索阶段划分与缓冲深度。** 有可表达的合法阶段方案时，先以有界的 `phases × slots` 空间探索重叠与容量的相互影响，再按结果扩展；不要默认沿用现有算子实现的阶段划分或缓冲深度。仅在固定单阶段下搜索 slots，不能记为阶段搜索。未开展其中某项时，说明具体能力缺口、成本证据或本轮范围及未覆盖维度；固定结构的模型同分本身不足以排除其他阶段方案的价值。
- **阶段变换须保留驻留与发射契约。** 跨 task 复用需显式描述版本和全部消费者；不能把每 tile 重载模型当作驻留实现。默认发射顺序下死锁只排除当前声明，适用时推荐连同 `issue_policy` 搜索；入口和覆盖记录见[内置搜索器接入](tool-routing.md#内置搜索器接入)。分别记录执行支持、变换支持、搜索覆盖和未知成本。
- **选择模型搜索时实际使用适用的内置搜索器。** 声明合法的切分、分核、流水及 slots 空间，再对搜索结果做全 case 同口径复评。算子实现中的固定值不自动构成搜索边界；固定或不支持的维度说明依据与未覆盖范围。入口及验收见[内置搜索器接入](tool-routing.md#内置搜索器接入)。
- `run_experiment` 的固定候选排名、动作登记、单点重放或局部 `CycleModel` 分析均不能单独证明族内搜索完成。结构探索、自动参数搜索和完整 case 复评分别记录；只调模板参数时明确未探索结构空间。
- 完整候选的来源、收益机制、风险和选择理由须可追溯，见[候选与测前预测](workflow.md#候选与测前预测)。模型搜索结果供参考，不要求采用第一名。模型缺失或关键差异不可表达时说明限制，可在授权范围内继续实现与实测；不虚构模型评分。
- **VF 成本须有来源与适用域。** 可使用实测回填、系数/公式或显式配置的外部预测；详见[VF 成本接口](../framework/vf-costs.md)。未知项不能用任意常数或端到端残差补成有效评分。预测排名、校准资格与设备收益分别报告；采用实现仍需同口径设备验收。
- 用户只要求实现侧试验、单点分析或历史复盘时按该范围执行，不强制启动搜索，也不记为模型驱动寻优完成。测后补建模型不得回填为测前搜索或预测命中。

## 工作目录与执行范围

使用安装的 `opmodel` wheel 和用户工作目录；先按[运行示例](wheel-commands.md)
核对版本、入口和模型位置。可编辑算子 YAML、用户 hooks、实验配置和允许覆盖的硬件文件。
仿真、模型执行和搜索由已安装的 OpModel 包提供。

安装目录保持只读。模型和候选须通过配置、依赖、容量和正确性检查。
遇到不支持的能力时，保存最小复现和影响范围，评估当前接口可表达的替代方案；
其他可执行分支按任务范围继续推进。

设备实验按用户任务范围执行；安装工具或查阅文档时不启动实验，已暂停的优化等待用户恢复。

## 从当前任务进入

先读取目标算子的参考、实现、已有 case、当前最快对照及模型记录，从已有资料恢复契约。只询问影响正确性、测量可比性或执行范围且无法从资料确定的信息。延续会话已有授权与限制；只分析或归档的请求不触发新实验，只建模时仅执行获授权的模型检查或搜索，不运行设备计时或 Profiling。暂停范围以用户要求为准。

确认以下输入；项目已有记录可直接引用，不要求用户重新填写：

- 算子数学语义、总输入形状、dtype/layout、支持范围、输出与副作用；有状态、别名、随机性或量化时补相应规则。
- 独立参考和原正确性标准、完整性能基线、当前实测最佳实现，以及单 shape、多 shape 汇总或运行时分发的目标。
- 实现后端、算子实现位置或待实现状态、目标硬件和编译环境、模型执行入口、成本版本及校准适用域。
- 本轮问题、允许改变的部分、实现与测量预算、停止条件，以及可用证据和产物位置。

通用契约不预设 BF16、特定容差、核数、Cube/Vec 配比、状态缓存或 cohort。参考来自用户指定实现或数学定义；没有生产基线时，将首个正确实现记为起点，明确缺少生产基线的比较结论。

## 组织一轮工作

按 [联合迭代与证据契约](workflow.md) 执行当前适用阶段，复用已有有效结果：

1. 冻结语义、独立正确性参考、完整计时边界及基线；使用模型时核对其数量、资源和依赖。
2. 提出结构实现族，按需要选择内置搜索或直接实现实验；实现前冻结候选、来源及收益假设，存在有效模型预测时一并保存。
3. 核对实际实现结构及适用的模型对应关系，通过编译、原正确性标准及适用行为检查后，再做同轮完整计时和必要 Profiling。
4. 分类解释偏差；影响下一轮选择时，在获授权范围内修正模型，经未参与拟合的样本验证及历史候选重放后继续。新设计方向按证据选择建模搜索或设备实验。
5. 分别保存实测赢家、有效模型版本、反例和复现入口。实现收益与模型校准独立验收；按目标、预算和用户要求结束，无稳定新收益时保留原控制。

模型后端一致性不能替代设备正确性或成本验证。各阶段资格、采样和记录字段统一维护在流程参考中。

## 减少无效实验

新算子接入、批量实现前，或同一方向反复失败／收益不稳定时，读取
[少走弯路的实验决策](experiment-economy.md)，按症状选择最小判别实验。
只验证会改变下一步决策的未知项，按任务需要选择检查与微基准。

## 候选来源与模型贡献

按[候选与测前预测](workflow.md#候选与测前预测)区分假设来源、搜索选择、
测前预测、实现实测与测后解释；字段统一见[记录与交付](workflow.md#记录与交付)。
搜索空间由代理或开发者定义，参数枚举不等于自动发现算法。保留当前实测最佳、模型较优
候选和有辨别力的反例；排名差异不足以支撑判断时按机制选代表，不只实现预测第一名。

## 按问题选择工具

缺少模型时按[标准模型接入](tool-routing.md#标准模型接入)建立用户模型；
分核、参数、阶段和 slots 搜索按[内置搜索器接入](tool-routing.md#内置搜索器接入)
选择入口；结构探索、图动作与搜索会话按该参考核对支持范围。
具体可运行示例见[运行示例](wheel-commands.md)。这些参考均随 skill 交付。
安装时默认获取兼容的最新版本，运行前核对实际版本与[工具路由中的能力边界](tool-routing.md#版本和故障处理)。

只需理论评估时停在模型侧，分别报告理论、校准与设备口径。设备工具链由用户环境提供，
本 skill 和 wheel 不自动安装 DSL 编译器、执行设备计时或提供真实 VF 成本。

## 交付与复用

按[记录与交付](workflow.md#记录与交付)分别报告实现、模型及运行状态，
保存可复现的算子实现、配置、来源和证据。明确实际搜索范围、同口径对照、正确性与收益，
以及已验证和未解决的模型偏差；未使用搜索时标明未使用，不宣称模型贡献。归档固定点只证明可恢复，
不证明完成寻优或校准。MFU/MBU 等指标仅在分子分母适用且来源明确时报告。

通过 `$ops-opmodel-toolkit` 或客户端的同名技能入口调用。所有案例和实验记录保存在
用户项目中；复用其他案例时只继承适用的机制与方法，不继承形状、阈值、芯片或历史结论。
