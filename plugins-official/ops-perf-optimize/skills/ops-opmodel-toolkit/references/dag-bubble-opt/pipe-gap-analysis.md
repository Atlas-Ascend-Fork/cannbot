# 空泡分析的输入与报告口径

与[工作流](../dag-bubble-opt.md)配合使用。本页限定报告含义，不提供额外分析程序。

| 输入或输出 | 应说明的内容 |
| --- | --- |
| 运行身份 | case、模型、有效参数、硬件和成本版本 |
| trace 范围 | 核/阶段、时间原点、结束点、cycle 单位 |
| 空闲观察 | 目标执行轨、窗口、事件或截图位置 |
| 阶段分类 | 起始填充、结束排空、任务交接或尚未归因 |
| 原因与实验 | 证据、假设、修改的用户配置和完整 case 结果 |

局部 trace 与完整 case 的时间窗口可能不同；同名不同 pid/tid 的轨道不混为一个执行单元。
同管线的指令可存在重叠，服务周期和不表示墙钟占用。
等待可同时有多个条件，不把多个等待数字相加当作可节省时间。

完整 trace 和压缩 trace 提供的信息不同。当前压缩格式没有独立 issue/gate 和控制轨，
需要这些信息时重新请求完整 trace，见[运行接口](../framework/runtime-and-trace.md)。

证据不足时保留“待确认”，通过合法配置变化及同口径复评检验。
模型未覆盖的成本或行为不靠任意常数补齐；设备结论需要相应实测。
