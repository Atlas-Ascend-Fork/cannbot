# README 与 QUICKSTART

## 模块范围

插件根目录的 `README.md` 和 `QUICKSTART.md`，以及它们引用的使用与设计资料。

## 设计思想

README 介绍工作流的结构、职责和设计意图，QUICKSTART 提供最短上手路径；执行规则与操作细节由对应 Skill 或使用文档维护，避免重复。

### README.md：结构与设计意图

README 只需说明：

1. **设计意图**：工作流的目标、分层原因，以及 PM、子 Agent、Skill 与 harness 如何分工。
2. **结构与职责**：各目录、组件和关键产物分别用于什么，彼此如何关联；操作方法链接到对应文档。

问卷调整、环境检查和缓存策略等流程修正不列为工作流新特性。README 不展开参数、探测步骤、缓存复用判据、权限规则或恢复命令；只在结构、职责或设计意图变化时更新相关概述。介绍路径时说明用途即可，不复制所属 Skill 的执行细则。

### QUICKSTART.md：安装与使用

QUICKSTART 面向第一次使用工作流的人，按两类用户给出可直接执行的最短路径：

- 普通用户：推荐在目标工作区用 npx 安装，无需克隆仓库。
- 开发者：推荐克隆仓库后用 init 安装，并展示如何复用本地 cannbot-skills 仓。
- 共用的启动命令、一个任务示例及结果位置。

前提只列必需项，详细操作链接到对应安装文档或 Skill。不要在快速入门中展开参数全集、SHA 与 dirty 规则、资产布局、恢复或回归操作。说明以实际支持的客户端与安装方式为准，不把某一个客户端的路径、文件格式或命令当成所有客户端的通用行为。

## 为什么运行说明与设计理由分开

执行任务需要的是能力入口、操作约定与交付要求，维护任务需要的是设计目的和变更边界。父仓、子仓、替换原则等架构解释放在 README 或维护资料中，不要求执行者为完成一个节点读完整套设计历史。

Skill 入口保留必要的框架、基础概念和资料路由，细节按需加载；维护 Skill 的工作区结构与基础设计思想保留在入口，避免读者尚未建立概念就被要求跳转。触发条件写在元数据中，正文不重复说明何时加载。

每条知识保留明确的权威来源，其他资料引用它而不是复制全文。开发者和 Agent 共享的仓库知识优先维护在仓内文档，具体分层见 [repo-* Skills](repo-skills.md)。示例只引入理解规则所需的背景，不让读者为了读懂示例额外调查无关领域。

## 维护方法

**每次维护工作流，都必须检查 README 与 QUICKSTART 的一致性，即使本次修改没有直接涉及文档。** 检查应结合本次变更及真实实现：

- 两份文档是否存在，职责和内容顺序是否符合上述约定，交叉链接是否有效。
- README 的结构、职责和设计意图是否准确，是否混入应由 Skill 维护的执行细节。
- 安装前提、客户端支持、命令参数、路径、Skill 和角色名称是否仍准确。
- 工作流入口、节点组织、交付位置或恢复方式发生变化后，相关说明和示例是否同步。
- 子仓同名 Skill 覆盖方式与实际安装行为是否一致。

发现不一致时只修订负责该信息的文档；检查后无需修改则保留原文，不为满足检查要求制造 README 差异。流程实现变化不自动要求更新 README，影响安装或使用时再同步 QUICKSTART 或对应使用说明。

文档中的支持声明必须有实现依据。命令或执行示例仅在实际验证后才能描述为已验证，不能把模拟执行、文档检查或启动成功写成完整功能验证通过。
