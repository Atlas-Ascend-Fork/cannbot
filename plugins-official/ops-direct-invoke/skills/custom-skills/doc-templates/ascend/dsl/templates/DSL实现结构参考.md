# DSL 实现结构参考

这是一张实现前的查找与组织提示，不是新的验收规则。算子的数学、支持范围、资源与同步以本轮冻结的 spec、DESIGN 和 Unit 为准。接口用法以本轮选定 Python 实际加载的 DSL 版本为准，版本核对沿用“运行工具”中的既有规则。

## 从本轮 DSL 快照找同类型样例

本页结构来自已拉取 DSL 目录中的 `first-operator.md` 和 `samples/vector/add/{README.md,add.py}`：前者讲清 Kernel 与 Host 的职责，后者展示公开 Python 入口、Host 启动、Kernel 计算和编译函数如何接在一起。工作流执行时使用**本轮** `$WORK_DIR/cannbot-dsl/`。

1. 从本轮 spec 和 DESIGN 摘出运算类别、输入输出形状、dtype、布局、掩码/归约、数据搬运和多核关系。先在 `$WORK_DIR/cannbot-dsl/samples/` 的目录名与 README 中找相同运算，再找相近数据流或接口用法；选一两个最贴近的样例即可。
2. 读所选 README 的支持域和实现说明，再读对应源码中的公开入口、Host、Kernel、编译函数和相关 API。只参考 API 用法和代码结构，记录样例路径、借鉴点与本轮设计的差异；依据当前规格与设计自行实现，不照搬样例实现、公式、tile、核数、缓冲深度或支持范围。
3. 如果快照没有同型算子，明确写“无同型样例”，再用最小样例参考代码结构，具体计算与接口分别按本轮设计和 `docs/zh/api/index.md` 定位。
4. 将本轮真正使用的 API 按计算、数据结构、搬运、执行、编译等主题一次定位到文档正文；复用环境报告中的解释器、包版本和已确认依据。样例与安装接口有差异时按实际加载版本核对。只有文档和公开定义仍不能说明的用法，才用当前候选的必要编译或已有相关用例定向验证，不逐接口另造探针。

## 一文件结构

以下是组成部分的示意，省略号必须用本轮设计和真实 API 填写；完整写法从本轮匹配样例取，不把这段当作可运行代码。

```text
模块顶部：所需导入、明确来源的支持域与常量
@kernel：执行设计中的设备计算、搬运和必要同步
@host run(...)：绑定本次参数，在函数体内直接启动 Kernel
build_program(...)：集中构造与 Host 参数对应的编译规格
公开 Python 入口：校验输入元数据 → 选配置 → 分配输出 → 调用编译程序 → 返回结果
可选辅助函数：只提取重复的校验、规格或布局推导，不把 Kernel 启动移出 Host
```

先把公开参数、Host 参数和编译规格的顺序对齐，再按设计填计算。实现后继续使用本节点原有的 TDD、固定 runner 和版本证据；参考样例不替代实际编译或设备结果。
