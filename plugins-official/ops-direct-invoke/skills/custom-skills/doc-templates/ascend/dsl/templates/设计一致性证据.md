# 设计一致性证据

本记录用于实现符合性验证，不是实现进度、性能报告或执行者的验收结论。沿用冻结 Unit 的 design_constraints 和 implementation.feasibility_checks，不另建一份设计规范。每项均须覆盖；obligation_ids 关联普通数值结果不能自动证明结构承诺。

## 规划与验证安排

设计规定保证的行为、强制结构和允许演进；Unit 规划本次交付的能力、允许写集、依赖、阶段范围及可落实的义务，测试再生成具体输入和断言。不另建完整设计验证矩阵，不按检查事项新增 Unit，也不预设算子、算法、形状或变体数量。原承诺及必要的性能、结构、资源和同步要求完整保留；设计承接选型依赖的参数和关系，实现决定满足它们的具体 API、地址、事件及代码组织，Unit 不把这些允许选择变成固定接口或额外补证。

规格是算子完整支持域的来源，Unit 可按设计允许的能力增量声明合法子域；阶段限制不升级为公开需求。首个数值闭环贯通真实入口、必要计算和写回，不要求一次覆盖全部规模、dtype、尾块和特殊值；设计允许后置的能力有明确归属和后继覆盖，首次使用前的补证及当前子域必需机制不能推迟，不能用占位输出或删除所选架构的必要结构制造闭环。全部 Unit 最终承接完整设计，不为迁就测试工具永久缩减支持域。

阶段域与最小合法场景直接沿用 Unit 规划 Skill 的定义：按当前 Unit 所承接设计路径/能力核对其最小场景及前序保留面，不强求全部 Unit 包含同一全局样例。来源和推导留在既有 Unit/报告，依据不足、与规格冲突或覆盖不闭合时按原协议交接，不为避开边界重选输入，不另建一套定义。执行与验收使用同一口径，不能只凭 YAML 可解析认定成立。

逐义务及 must_distinguish 的必要子条件判断可达性。对于正常支持域行为，规格合法域、当前 Unit 域和触发条件内应有可满足的构造，再沿真实参数选择与执行规则推导所需行为。能力仅来自当前 Unit 与前置，不能借未来能力凑触发；可调参数、资源有解或标签不代表实际选择。每个覆盖场景分别与同一义务的共同前提及 Unit 域联查；互斥场景由不同用例分别覆盖，不要求同一输入同时满足。不能因为每个场景单独有解就忽略共同前提将其中某场景排除。一个依据可覆盖多个条件，不作组合穷举，也不要求规划提前生成用例。

原设计明确要求的拒绝或域外行为按其自身契约核对故意违反的条件、其余前提、公开入口和结果，不要求故意违反的条件同时落入正常合法域。其余前提和该 Unit 已承接的能力仍须满足，不借负向输入假定未来能力或扩大正常计算支持域。同一调用要求拒绝与成功返回时属当前契约冲突，不能只登记后冻结；上游来源有冲突按原协议交接，规划不自行解释规格。未找到构造不等于已证明不可达，未知项保留具体缺口。

沿用 supported_domain/domain_constraints、input_conditions、behavior、must_distinguish、observable_result、coverage_axes 的原语义与必需格式。Unit 域表达阶段范围；同一义务的 input_conditions 会约束所有绑定用例，只填写该义务各覆盖场景共同需要的真实前提，不把单个示例的精确取值升级为整项限制。behavior、observable_result 与 coverage_axes 用现有字段说明场景及适用条件，示例与整项承诺范围须一致；可由不同合法输入完成的覆盖不强制合并到同一输入。不为满足字段而删除共同前提、拓宽 Unit 域、丢弃覆盖轴或降低判别要求；确有不能共用同一组前提的独立义务时，允许在现有义务结构中分别承接，不强制新增 Unit、字段或场景数量。参数推导或条件作用范围变更时联查 supported_domain、domain_constraints、input_conditions、behavior、must_distinguish、observable_result、coverage_axes 及引用说明，不能只放宽等式而留下正文仍限定单个示例。可用现有公开谓词表达的条件按契约承接，不能表达的关系说明依据与证据安排，不虚构工具能力。

当前 TDD 契约能表达的数值及公开行为要求写 verification_obligations，数值判别遵守冻结比较口径和容差；数学上不同不等于当前条件下可检出。依赖源码、编译产物或外部执行证据的要求写 design_constraints 或 feasibility_checks 的 review_evidence。错误码拒绝沿现有黑盒 raises_error 入口，由这些现有证据字段承接来源、责任、真实执行证据及到期时机，不写异常 TDD。规划与当前允许验证范围不相容时报告缺口，不擅自扩权限、延期或用普通输出断言替代拒绝；不把黑盒 ID 或源码检查当作已实跑。域外正常返回不使用错误路径豁免，按其实际返回语义与可表达条件安排。混合要求分别承接并保留必要联合证据；不把数值不可观察的子项留在数值 must_distinguish 再用“另有审查”豁免，也不因不能数值判别就删除原承诺。只剩证据检查的碎片不伪造空壳 Unit 或数值义务，沿用现有 schema。

review_evidence 沿用 artifact/check/pass_criteria/reject_examples，说明对象或公开验证入口、版本关系、责任阶段、判失败依据与原设计全部适用判据。反例须实际违反原承诺，不强迫每项发明另一套算法，不能因 API 名称、调用形式、地址或事件编号不同就拒绝设计允许的回退或等价机制；按实际输入/结果表示、有效范围和消费关系检查，不为每个普通选择另建证明。前置补证沿用 before_step/on_failure，最小实现与验证先后可落实，不能要求代码不存在时已通过，也不能只写“后续检查”。不向生产接口植入探针；缺少工具能力或权限且无保留原要求的办法时如实交接。

在现有 Unit 和报告中保留一份义务到原条款、责任与阶段域、可构造依据、公开判据或专项证据的对应，引用已有推导，不生成完整输入配方、Case ID、Golden 或未来结果，不新增字段、台账或固定表格。条件、验证方式或归属有误时在本阶段修正正文并保留去向，必要时按权限调整能力边界和依赖；迁移不降低标准、不延后首次消费前补证，改变冻结设计或规格须按原协议交接。

独立规划验收从实际 DESIGN 承诺核对 Unit 集合的能力、义务及全部必要子条件，不只沿作者映射表。检查可达性、归属、可观察性和可落实判据，反向判断当前安排是否仍允许违反原要求；字段齐全、依赖闭合或另有报告均不代替这些判断。不替测试生成完整用例，不执行未来补证；发现阻断后收齐可独立完成的轻量检查，受阻部分注明原因。必要缺口未闭合不冻结，已有明确且仍有效的审查结论按原规则复用。

## 实现与证据验收

### 完成含义

数值通过只说明对应版本、输入与范围的数值用例满足判据；尝试结束只说明本轮操作已经终止，包括阻塞退出。能力完成须相关测试、当前设计约束、到期补证及受影响回归均有有效依据。前两者、证据记录齐全或哈希匹配都不能单独推出能力完成；自检也不构成最终独立验收结论。这些含义不新增 Unit/证据字段、进度账本或调度状态。 数值差异先核对独立主参考职责、约定计算/累加精度和舍入边界及实际比较策略；同舍入模拟一致只支持相应路径与输入，比较失败也不直接证明设计错误。改变已冻结的参考或精度标准须按原需求变更规则处理，不能为消除失败自行切换。

### 当前 Unit：实现、反证、决定

1. 实现当前能力：先读该 Unit 原条款、强制承诺、允许自由度、全部适用判据和补证时机；在原写集内选择落实原关系的具体 API/等价机制，按实际版本补齐必要依据并完成实现与适用 TDD；普通选择不返回设计，无法落实关键承诺或超出允许范围时按原协议交接。已有正确能力可复用，不补造红灯；需要首次使用前完成的补证不后移。
2. 反证自检：数值转绿后，重新读取实际源码、必要已有产物与原条款，逐项核对 review_evidence 的 check/pass_criteria 和已有 reject_examples。先判断当前实现是否仍属于“数值正确却违反承诺”的反例，再检查其余适用要求；反例不是穷尽清单。结合实际 API 的输入/结果表示、归约/广播与消费范围，以及真实 dtype、数值/边界语义、索引、实际生效参数、搬运次数、并行、同步和生命周期判断，不只看源码拼写、符号代数或阶段名称；数值等价不能豁免原设计冻结的搬运粒度、次数、并行或同步承诺。读取被引原始结果及适用的命令、版本和退出码，确认成功、失败或未执行的真实范围；自己的实现摘要、文件名、记录数量和哈希不能代替内容。结论与原始内容矛盾或证据不足时保留具体缺口，不能先认定满足再补理由。
3. 依据结论行动贯穿编码、诊断与自检，不等数值转绿。发现当前 Unit 已到期的强制承诺不满足、补证未完成或依据不足时，停止推进后继；权限内可修复的继续当前能力，无法完成或需要改变冻结契约时，保留事实与未知项，按原协议报告阻塞并结束尝试。设计允许的等价选项和未到期且尚未消费的后续要求按原安排处理，不一律升级为当前阻塞；全部到期要求与必要回归成立才转入下一 Unit。记录阻塞不构成豁免，不能将受阻能力标为 completed 或用后继/全量数值通过抵消；若客户端使用待办清单，已完成的阻塞分析与未完成的能力分别描述，沿用其既有状态，不新增阻塞枚举。原生验收、重试与预算照常生效，不另设流程或绕过裁决。

以上在同一执行会话内完成，不派发逐 Unit Agent。条款定位、实现位置、原始事实和未关闭项增量写入既有 checks；共享修改同时复核受影响前序承诺。来源足以证明时直接引用，不为每个 Unit 强制编译、插桩、全量检查或性能采集；需要真实编译/设备证据的到期义务仍按原安排完成，不扩大实验。

### 记录与版本

中间记录沿用下列 checks 条目，不新增进度账本或通过状态；可暂缺完整 snapshot，不能据此声称完整性检查通过。全部 Unit 声明源码落地后，结合最终源码补齐完整 snapshot 与证据。中间红绿阶段不要求运行完整检查，也不得为生成快照而提前创建后续 Unit 的实现。运行 `"$PYTHON" "$WORK_DIR/scripts/check_design_evidence.py" --work-dir "$WORK_DIR" --snapshot` 获得当前 snapshot 和 required_checks；程序只打印、不生成通过记录。required_checks 的键为 Unit/section/从0开始的条目索引，绑定 Unit 文件哈希，Unit 修订后旧定位不再有效。

```yaml
snapshot: <上述命令的完整 JSON 对象，也可用等价 YAML 表达>
checks:
  - id: U01/design_constraints/0
    finding: <原条款及全部适用判据、实际实现与原始依据、反例核对和未关闭项；结论不预设满足>
    evidence:
      - path: operators/example/example.py
        sha256: <引用文件的实际 SHA256>
      - path: implementation/raw/compiler-report.txt
        sha256: <原始编译资料的实际 SHA256，仅在需要时引用>
```

证据路径使用 work_dir 内相对路径或绝对路径，外部编译材料保留只读副本与来源。用测试证据时说明输入与断言如何排除违反承诺的实现，不以参数存在、注释或 Host 拼装事件代替真实结构，不要求实现阶段性能采集。

完整性检查仍用 `"$PYTHON" "$WORK_DIR/scripts/check_design_evidence.py" --work-dir "$WORK_DIR"`，只检查约束/补证覆盖、当前设计/Unit/声明源码与原始证据的哈希，不读取自然语言裁决语义。未知、不一致的 finding 也可能通过结构检查；语义结论由执行者自检和最终 verifier 的独立审查分别承担，不能按脚本退出码继承。

### 修复与收口

修复先结合全部未关闭反馈、当前实际代码、变更及适用证据，按 Unit 依赖、首次消费时机和共享改动影响定位当前阻塞及范围，核对反馈建议与冻结契约相容；反馈不授权推迟前置要求或改变设计。沿用原报告，不另建清单、字段或交付件。未完成能力继续上述三个动作；已交付能力不机械重演红绿或重叠依赖闭包，首次消费前的补证不延后。条件未变且仍超出本节点权限时，只复核条件并引用有效证据，按原阻塞协议结束，不重新展开后继或完整调查；不将文档交接描述为已实现自动返回设计节点，harness 原生重试和退出机制不变。

验收反馈在原报告中保留问题的前置关系和影响：当前强制偏差及到期证据缺口优先于依赖它们的后继实现，不以问题编号代替依赖判断，也不将所有缺项默认视作可独立推进的待办。受阻后继仍属于整体交付未完成范围，但不能要求先完成后继、再关闭前置偏差，也不能把待设计裁决安排为全部 Unit 完成后的收尾事项；明确权限内可继续的修复或需交接的缺口，建议不构成变更或跨阶段调度授权。整体仍按原标准判定，不新增部分通过状态、不豁免后继最终交付责任；历史顺序问题不单独否决当前已正确修复且证据有效的实现。

正常修复可直接修改原写集，不要求每次复制工程。为定位而临时省略当前路径应执行的计算、关闭阶段、固定中间值、缩短处理范围或绕过依赖的变体，沿用 implementation/raw/ 的隔离权限；检查实际写入和加载的源码及其依赖，不因启动脚本位于隔离目录就认定已隔离。诊断变体不得修改正式模块及其依赖源码或冻结输入，不自动成为修复；采用其中改动须重新核对当前 Unit 的完整契约及设计允许范围。无法在现有权限内隔离时保留未知及已有证据，按原阻塞规则处理；本要求不新增诊断程序或设备实验。

从备份、检查点或旧版本恢复/替换源码也按源码变更处理。恢复前在原执行报告简记来源及已知的未实现、诊断改动和未验证项；备份不要求已通过，但存在备份不代表可信或已验收。恢复前后读取实际差异，核对是否带回诊断改动、覆盖后续修复，以及受影响能力和结论；恢复后、继续诊断或推进 Unit 前完成核对，不只看复制成功、文件时间或哈希。

先处理已知、可由当前材料确认的设计偏差，再完成必要正式回归及到期专项验证；须执行才能判断的项仍真实执行，不能预先假定通过。已有完整结果有效时复用，之后改代码或发现新缺陷则按实际影响修复、重验与更新绑定，不规定只能一次验证，不新增私有循环、预算或设备实验。

更新从实际源码与原始执行/编译产物出发，联查 finding、引用、说明和摘要；同一事实保留一份依据。“已排除某原因”等诊断结论仅在对应源码、输入、环境及观察前提仍成立时复用，恢复或替换相关代码后须核对这些条件；前提变化或无法确认时保留历史结论及其版本，当前归因标为待确认，不能只刷新哈希继续沿用。未受影响且仍适用的材料继续引用，失效内容保留历史并说明原因；仅解释变化且原始证据有效时补说明，缺少真实证据时由执行者补齐。必要重验沿用已有失败用例和受影响回归，不默认全量重跑或增加实验。最终正式放行仍满足既有版本绑定规则，不给旧结果补签；snapshot、checks 与所引材料对应准备交付版本。报告和最终回复区分已完成能力、适用数值结果与未关闭项；尝试因阻塞结束时明确本轮未完成，不以证据清单齐全或待办全勾选声称实现完成。

最终独立验收针对当前源码、全部 Unit 的本阶段要求及适用证据，独立审查整体连接、强制承诺和后续改动；不只接受自检结论，不重复执行有效设备验证。历史红绿顺序、自检时机或已正确恢复且当前证据有效的历史诊断变体不单独构成否决理由，不为补齐过程删除正确能力或重演实现；当前源码不得残留削弱计算的诊断改动，证据的真实性、覆盖、版本对应及设计规定的运行时同步/生命周期要求仍须满足。有具体疑点时定向追查相关记录，不默认全面回放实现会话。精度修复改代码后同样更新受影响项，并基于最终源码重新做完整性检查；无源码变更则复用有效记录。既有权限和预算内的修复、验证和证据整理的先后或重复次数不单独构成验收门槛，当前强制承诺和必要证据仍须满足。保存历史记录及修订原因，从缺失或失效项继续，不清空重新编造。
