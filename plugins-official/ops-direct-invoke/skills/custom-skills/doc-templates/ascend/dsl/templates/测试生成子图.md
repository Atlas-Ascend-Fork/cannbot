# 测试生成子图的共同方法与证据

主图保持 test-generator 入口。新子图由 harness 调度 Golden、白盒、TDD 三路并行准备，再由 integrate 完成集成、CPU 检查、自检和修复，其独立 verifier 最终放行。节点不再次派发子 Agent。已冻结的旧八节点运行继续使用原图与对应旧阶段约定，不迁移状态或中途改图；正式资产均只在最终独立验收通过后冻结。

## 输入、暂存与写入

规格、需求、DESIGN、selection、Unit 和已验收环境直接消费，不重新裁决语义。使用中发现同一公开调用的合法性、期望结果或义务含义冲突，按原协议交回相应责任阶段；“上游已通过”或“本节点不能修改”不构成当前交付放行依据。已明确责任、时机和方法的未来补证尚未执行，不因结果不存在单独阻塞，也不提前标为通过。白盒/TDD 草稿为公开分组写入入口的 JSON 行数组，不增列或适配 Unit，不把暂存内容作为第二用例真源。草稿、汇合、纠错记录须索引本次输入版本；重试先用当前有效正式内容，不盲目回灌旧草稿。

正式 CSV 由集成节点唯一写入；恢复已有流程时，按冻结图的阶段权限保持单一写入者，使用 Skill 的 update_case_group.py 标准输入接口，先白盒校验、再绑定 TDD 实际可运行 branch ID。DESIGN 引用不能未经核对当作白盒 ID；CSV unit_id 按 Skill 为原生 Unit ID 小写，进度消费方只做关联映射，不改写 CSV 或 case ID。保全用户 performance 与其他未修改分组。

## 真实输入、派生参数与覆盖事实

各节点仅核对自身职责内使用的事实。当前有效的标准行或正式 CSV、实际调用输入及冻结设计规则是依据；Case ID、condition、note、报告摘要和人工标签不是参数事实来源。先确认所用输入配方、标量及调用覆盖，再按本次设计实际参数选择和执行规则推导需要引用的量；依赖输入内容的有效数量或行为使用已有适用物化/执行证据，不凭 shape 或配方名称猜测。推导或物化不代表目标实现已执行。

一行含多次调用、内部切分、循环或边界变化时，对会改变目标结论的部分按实际条件分别核对，可用完整的规则及有依据的等价划分说明，不要求穷举所有元素。结论限定到相应调用或分块，不能取最后一次/最后一块的参数代表整行。行级、调用级和分块级计数明确口径；无法确认或尚待后续节点绑定的关系保留依据及责任，不能据此宣称覆盖，当前阶段必需事实缺失仍按原阻塞规则处理。

必要参数及其推导在本节点已有证据中保留一份来源定位与适用版本；condition、note、覆盖映射及报告优先引用该依据，只保留理解所需摘要。后续节点复用当前仍有效的原始材料，独立审查真实输入、规则与结论的关系，不默认重写另一套推导或复制完整数值表。已有核对足够时不新增工具、格式、探针、全域扫描或设备实验，也不为此等待并行准备节点尚未交付的产物。

修改输入、标量、调用序列、相关设计依据或推导方法，或修正覆盖判断、判别能力声明及既有证据安排的说明后，先核对真实依据与影响，再联查当前可写的 condition/note、分支绑定、义务映射、统计、证据正文和摘要；只改说明未改输入时也须核对关联位置，不能仅在返工总结宣布修正。有效旧材料直接引用，不重做有效验证；失效结果保留来源并按现有责任补齐，不能只更新行数或哈希而保留原覆盖结论。自身无权改写的历史审查报告保留，在当前记录说明修正关系。暂存草稿与正式 CSV 的写入边界不变，不用旧草稿覆盖已纠错的正式版本。

绑定与覆盖分别说明依据。按设计及公开契约区分真正的触发谓词与示例参数；声称具体条件被覆盖时，当前输入及实际派生行为须满足全部必要谓词。仅有同一设计来源、相同路径名、参数较大或相同标签不足以证明；有依据的路径关联只支持该关系，不能冒充某个具体输入/形态的覆盖，也不通过默改绑定含义、删条件或缩小原承诺获得通过。

## Unit 义务与本阶段边界

沿用 $DOC_TEMPLATES_DIR/templates/设计一致性证据.md 的“规划与验证安排”理解冻结义务。测试负责将当前公开调用可观察的行为例化为真实输入、配方、断言与义务/分支关联，实际推导触发并证明其判别范围；不重新规划全部 Unit、复制设计验证矩阵或新增原义务。义务 ID、路径覆盖和准备校验通过均不代替必要子项的实际依据。错误码行为沿规格已有黑盒 raises_error 入口及 Unit 的 review_evidence 承接；TDD 不接受异常 expected，不将其包装成正常输出，也不删除原拒绝承诺。若冻结 verification_obligations 已误放必须由异常 TDD 承担的要求，按原协议交回规划，不在测试节点擅自迁移；正常非异常义务仍须完整覆盖。

设计的强制结构和 Unit 已分配的源码、编译产物或外部执行证据，保留原责任、入口/产物、判据及时机。未到期时注明待对应阶段验证，不因为未来结果不存在而否决测试准备，也不以普通数值、shape、设备归属或重复调用冒充已观察到结构/时序。本阶段职责内的输入与契约检查仍须完整执行，依赖三路成果的完整 CPU 与缓存检查留给集成；原设计需要联合证明的关系不能被拆散。

当前例化遇到义务条件与 Unit 域、观察量或判据冲突，或缺少可落实工具/安排时，保留原条款、实际输入和证据、影响及建议责任阶段，按原协议交接；不修改冻结 Unit、转移责任、造占位 TDD、删条件或改 excluded 来补覆盖。当前输入未检出错误，只能限定该输入的声明，不能直接推导所有合法输入都不可检出。影响当前用例合法性、期望、可执行性或义务绑定的冲突未关闭时，当前草稿与集成都不得判 pass；记录上游责任、无权修订或“尚非完整校验阶段”不豁免已证实不可执行的条件。接收契约可用公开 --check-unit-contracts 模式预检，不能将域约束支持的键当作输入条件 relation；即使当前行碰巧满足，仍须实际绑定冻结义务的全部条件。上游义务明确且只是未来补证未到期时按原安排保留，不要求为草稿提前生成并行资产或执行全量 CPU/设备结果。测试资产通过不代表实现能力或专项补证通过。

## 判别力实验的证据前提

TDD 的必要证据是原义务与真实输入、必要触发、断言/比较口径和判别范围的对应关系；在已有 tdd-evidence.md 中保留一份依据及版本索引。condition/note 只写必要摘要，派生量可用规则及有依据的等价划分说明，不要求逐块全集、逐变体误差表、检出率或逐位结论。契约明确的逐位、调用生命周期及性能/结构约束仍须保留，不能为减文档删改义务或断言。

TDD 草拟的执行、自检与独立验收只核对用例的合法输入、必要特征、真实触发、公开断言、判别范围及义务绑定，不模拟完整算法裁定设计精度；不读取、导入或等待并行 Golden/runner，即使其先落盘或先通过。优先用冻结规则、公开配方定义及不依赖并行产物的局部检查提供依据，不按 must_distinguish 数量建立故障变体全集或新增实验。正式数值用例仍使用 Golden，但调用留给汇合后的准备及后续真实目标测试；单元契约的只读预检不依赖 Golden。可观察数值/行为义务不能以未检出、未建模或无授权的结构转交补覆盖。

若已开展实验，先确认同组物化输入下、原比较口径中的正常版本通过，再解释目标缺陷；对照保持输入、seed、dtype、断言及必要上下文一致，只改变目标缺陷，并核对改动是否实际触发。正常版失败时对照无效；guard 拒绝说明未执行，裁剪/简化屏蔽目标行为说明未建模，未触发也如实限定。已有自写数值模型或精度实验只证明对应模拟与输入，超限作为风险交接，不能据此认定真实目标失败、所有设计实现不可行或单独否决 TDD 草稿；不把模拟器失败当作公开工具契约不兼容。发现输入条件互斥、判据不可消费、必要特征不可达或覆盖声明无依据时仍按用例缺陷阻断。参考职责交 Golden，跨分支兼容性由集成核对，真实目标精度沿正式执行；风险交接不豁免已明确的规格冲突或本阶段必要覆盖。

有效对照中通过原判据只支持“本输入未检出”，不自动证明逐位相同、数学等价或所有合法输入均不可检出；无需为记录未检出额外证明更强的等价性。若契约确需或报告主动保留这些更强结论，须有对应依据。纯结构及数值不可观察部分保持 Unit 已分配的 review_evidence 责任和时机，未到期不提前宣称通过，普通数值通过不替代必要结构证据。

提交前按必要结论自检原始记录与当前行、条件和证据摘要一致，区分已执行结果与分析判断；计数如保留则由有效记录核对，不要求另建统计报告。修改输入、正常版本、探针或比较逻辑后按影响重验对照；仅修正说明时核对原记录并联查已有引用，复用有效用例、预检和计算结果，不因文案轮次重跑整批或增加变体。失效结果保留并标明原因，不能改文字掩盖真实失败。

独立验收阻断用例非法、触发不可达、判据无效、必要覆盖/结构承接缺失，或证据不支持所用必要结论的情况，不认可虚假覆盖与归因。非必要精确值、冗余统计或措辞差异不单独升级为新的覆盖门槛；可依据原记录更正或删去多余陈述，保留必要结论和映射，不强制保留后再逐项证明。验收只核对所提交证据，不替作者补实验或重复整批执行。

## Golden 与 CPU 方法

默认与完整数值策略沿测试 Skill 的公开契约：未指定时浮点 staged_relative、整数/布尔精确比较，明确要求优先。仅列阈值或第一阶段通过条件不视为排除第二阶段，须核对完整标准；默认 reference_mode=native 并准备独立同精度参考，缺失或异常明确失败，不用截断主参考自动替代。同精度参考由 Golden 按 spec 与合法的冻结 DESIGN 数值链独立确定计算精度、累加及中间舍入边界；不从输入/输出 dtype 或原始高精度参考写法推定全程 fp32。规格明确要求优先，设计合法选择的低精度运算须表达对应舍入；高精度主参考不照搬设计路线额外的低精度舍入，规格明定的量化、舍入仍忠实表达。只承接影响数值的已确认边界，不要求设计提前枚举 API 或调度。规格先冻结实际策略，准备与集成核对正式 runner、同精度参考和逐例结果绑定；当前能力不支持不能借旁路函数或后续设备责任放行。公共策略有效回归可复用，避免每算子重造比较器与全量对拍；同精度参考如需运行，使用同一物化输入及约定精度。

【Golden 独立数值核验】 Golden 子任务负责参考实现及其计算方法的独立正确性依据。从冻结需求与 spec 的数学、数值及异常语义出发，选择适用的权威 CPU 参考，或独立推导的朴素计算、可解析构造与有依据的性质，实际交叉核验 Golden。独立参考的期望值计算不能调用 Golden 数值函数或其私有计算辅助函数，也不能来自候选实现、模型预测或复制设备调度；函数改名不构成独立性。独立性不禁止按 spec/DESIGN 实现同一条已确认舍入链，但不能仅因候选红灯追加未经确认的转换、补偿或改变阈值；发现漏表达已确认边界时按来源修正并使受影响证据和缓存失效。执行自检和验收从实际函数核对两份参考的数值路径及来源，不只检查输出 dtype 或绑定存在。对需要比较的两路计算使用同一组真实物化输入，选择合法的小规模场景，覆盖会改变参考正确性的分支、dtype 与数值边界；不以样例数量或为每个正式 case 另建独立参考作为完成标准。小场景不能违反冻结输入域，也不写入或替换用户 performance 行；最小合法规模仍很大时，选择有来源的可解析构造或其他可执行证据并明确局限，不能虚构小形状结果。

【独立证据与判据】 在已有 golden-evidence.md 中记录参考来源及版本、独立计算路径、诊断代码与输入、Golden 版本、命令/退出码、两路结果或可复现差异，以及适用语义、核验范围和未解决缺口，不新增记录格式。已有且仍适用的证据直接复用；计算方法、相关输入或语义变化使证据失效时，补齐受影响部分。新增 case 本身不使整套核验失效；发现具体未覆盖语义、版本不适用或结果矛盾时，说明其影响范围与缺口，不默认重验整个 Golden。性质检查只证明相应性质，不冒充完整数值对拍，也不能填补仍影响参考正确性的关键数值证据缺口。权威接口不适用时说明原因及替代证据，不强行套用接口；沿用已确认的精度与特殊值语义，高精度诊断不能擅自改变舍入/转换顺序、替换权威参考或增加生产准入阈值。交叉核验不一致时先定位 Golden、输入或参考自身的问题，禁止放宽标准使其通过；冻结需求或规格冲突按阻塞交接要求终止。

【CPU 资源安排】 汇合后、首次完整 TDD 校验及缓存准备前，根据真实 shape、dtype、调用序列及参考算法估算主要输入、输出和中间量，记录估算依据，区分估算与实际观测；在当前授权资源内确定执行顺序和有界处理策略。按 case 及调用序列顺序物化、检查和释放已不再需要的数据，保留跨调用语义所需状态，避免把所有大 case 的输入与期望同时驻留内存。不为提速自主增加并行大用例、安装依赖或改变已确认环境。

【大用例的参考计算】 保持纯 CPU Golden 与固定公共接口；必要时优先沿独立的 batch、head、输出块等合法维度分块，避免无必要地展开整个中间矩阵。涉及规约分块、重排或中间精度变化时，须按冻结数值契约说明并核验其适用性，不以数学实数等价直接证明浮点结果等价；采用的参考计算方式先纳入上述独立核验，再用于全量计算和缓存。资源不足或数值等价性未解决时保留具体 case、估算/实测与尝试记录并终止，不改 shape、dtype、seed、调用序列、用例状态或阈值来完成检查。

【CPU 职责与证据复用】 CPU 节点消费已验收的 Golden、固定入口及适用独立核验证据，落实完整测试资产在 CPU 侧的可执行性与已有要求的一致性。核对当前版本和证据适用关系，不重新调查参考来源、实现另一套独立参考或为每个 case 推导新性质。使用中发现具体矛盾或证据不适用时，定位计算路径、输入、版本、原要求及受影响范围，按原协议交接；不能以 Golden 自比较填补缺失的独立正确性依据。

【全量 CPU 检查】 遍历 blackbox、whitebox、tdd 及非空 performance 分组全部 active case 及其调用序列，物化真实输入，按已确认规格、设计、用例及公开测试契约落实适用检查。数值用例执行 契约指定的独立主参考，或复用当前版本的有效缓存；检查参考输出数量、shape、dtype、NaN/Inf 语义及已有适用业务断言。缓存准备成功只证明参考计算与存储完成，缓存命中只免去重复参考计算，仍须核对该例真实配方、输入关系、参考输出和适用断言，不因此自行新增判据。沿用 Skill 的缓存身份和校验入口，不只按 shape/dtype 手工复用其他 case 的期望，不修改共享缓存工具或把缓存可读取当作语义正确。异常用例核对实际输入违反的规格前提及预期错误声明，未执行目标接口不能宣称其已正确拒绝；行为用例执行适用 CPU 检查，设备归属、目标输入不变性等依赖目标实现的行为保留待对应阶段验证。不导入目标实现，不将参考计算结果视为目标实现已通过。

【CPU 诊断与判定】 CPU 不要求为每个 case 新增独立性质或重新设计正确性标准。临时推导的性质仅用于定位具体疑点，先核对数学前提、实际物化输入与有效计算范围；只有证据支持违反既有要求时才能认定候选缺陷，未经证实的假设不能成为新增准入标准。辅助检查与已有正确性证据冲突时，区分判据、辅助脚本和候选资产的问题；自身检查错误在本节点修正并按影响复核，不直接转交为候选缺陷，也不以辅助脚本出错为由忽略真实问题。未能确认的归因及证据缺口如实保留，不通过改测试资产或放宽原标准消除冲突。

正常参考、故意缺陷对照与目标实现的结果，按实际执行对象、来源/版本、输入及比较口径、范围、退出结果和用途区分，在现有报告索引原始资料，不新增字段或私有结果协议。可选诊断不成为必做对照实验。优先使用已确认的公开隔离能力，不猜造输出参数；公共入口共写路径时保留覆盖前后原始结果及来源，明确当前适用的正式证据，不改结果内容或补哈希冒充绑定。不只凭文件名、目录或 passed/failed 归属结果；对照失败不是目标实现失败，CPU 通过不是设备通过，后续正式放行仍消费实际目标版本与范围的绑定证据。

独立小规模核验与全量逐例 CPU 检查分别记录用途和覆盖范围，不能互相替代。主参考的精度、舍入及内置比较标准保持已确认契约；默认完整两阶段使用高精度主参考和独立同精度参考，显式其他策略沿其确认要求，不一概强制双参考；独立诊断不自动成为生产门槛，也不以自比较证明参考正确。已有证据或缓存有效时复用，仅对缺失或失效范围补齐；当前阶段的完整校验和全部适用 case/调用检查仍须完成。CPU 耗时与内存信息用于计算可行性和复现，不作为生产算子性能收益或新增验收阈值。

## 集成复核边界

Golden、白盒、TDD 准备分支分别负责本分支语义、输入触发及判据的独立验收。集成执行、自检和独立验收共用以下范围：确认准备裁决及版本适用，核对正式写入、跨分支关联、Unit 转交承接、完整覆盖、CPU 可执行性及集成实际修改。不因进入新节点就重新调查参考来源、推导单分支全部参数或重做已有效的独立核验。

只有原报告明确检查、内容和决定结论的依据未变且不受汇合或修改影响的结论才可复用；路径相同、上游整体 PASS 或作者声明不构成充分依据。发现具体矛盾、遗漏、变更或失效时定向复核受影响事实及关联；范围不明则扩大必要检查，真实缺陷仍须关闭。单分支漏检不因责任划分而豁免，未检查项不能继承通过。独立验收自行判断适用性，不替作者补证或重跑有效检查；未来设备和结构证据仍按原时机验证。

## 四节点测试集成与恢复

本节用于含 integrate 的新四节点图；不替代旧八节点图中已派发任务的执行与恢复约定。三路准备各自执行和验收，集成依赖三路通过；CPU 与静态自检由同一执行者组织，最终独立审查由 harness 派发 integrate 的 verifier，不再调度 review/cpu/fix/final 或嵌套子 Agent。

集成首次汇合尚未写入的内容时，先从已验收草稿串行写入并校验白盒，再完成 TDD 绑定、写入及声明域门禁；资源安排先于完整 build_tdd_cases.py 和缓存准备。正式 CSV 是消费真源；修复或重试以当前正式内容及原始写入/校验记录为准，保留已提交、已修正分组，只补有证据确认尚未写入的缺失部分。已有但未验证完整的内容补校验或定向修复；归属不明时先定位，不因中断无条件重做汇合、整表重建或用旧草稿覆盖当前内容。

默认串行执行 CPU 工作和静态自检；仅在启动前已有适用于当前客户端的可靠后台执行、真实退出结果及恢复机制依据时，才允许二者重叠。安装了后台命令不等于这些能力已经确认，不先启动后台再试探如何回收。确认可用后，记录 CSV、Golden、固定 runner、辅助模块及相关输入的候选身份，CPU 工作沿用本轮已有执行时限和资源约定，同一执行者只读自检，不派发 Agent、另建调度器或私有重试。后台记录命令、进程或会话身份、启动时间、输入版本、日志位置及真实退出码；结果由原执行产生，不以进程不存在或启动成功推断通过。日志与逐例结果只保留一份，报告引用。

CPU 运行期间不修改其读取的资产，自检问题先记录。工作结束并回收结果后统一修复；确需提前结束时只处理已确认属于本次任务的进程，并保留终止结果，不能把终止视为成功。无法可靠后台执行或确认退出结果时串行完成并记录原因，不新增脚本伪造并行，也不以不并行为拒收理由。

修复后按共享方法补齐失效的校验、Golden 核验和 CPU 证据，最终保持完整校验及全部适用 case/调用通过；仅说明变化且原事实有效时不重复计算。经公开准备入口重新生成本工作区 runner/辅助模块副本属于允许的准备工作，修改外部公共源码或直接改写其公共实现仍被禁止。最终候选须包含全部必需模块，并有适用于当前版本的公开接口、准备来源/加载身份、Golden 元数据及实际比较器绑定证据；存在性或缓存校验不能替代入口兼容性。独立 verifier 审查这些证据，不重复执行有效测试，也不要求提前加载尚未实现的目标。

验收失败通过 integrate 的原生重试返回同一执行者职责，不使用 final→fix 回滚边，不恢复旧草稿或复制 .workflow。重试先读当前资产、原生反馈和报告；进程可能尚存时，依据进程/会话身份、启动时间、命令和输入版本核对归属，不能只凭 PID 判断，也不重复启动或杀死未知工作。可安全接续或回收的结果按身份复用；无法确认的归属或必要证据缺口如实阻塞。真实上游冲突按原协议结束；预算耗尽退出，不无条件新开轮次。

执行者交付 integration-report.md 与实际测试资产，索引自检、修复及原始 CPU 记录。独立验收报告存于 .workflow/reports/，final-report.md 仅作本次报告与版本索引，不能代替 harness 裁决，不列为执行者预先交付条件。通过后才冻结测试资产；后续实现仍以整个 test-generator 子图通过为前提。

## 检查完成与发现缺陷

本节关于独立检查节点的交付适用于旧八节点图；新图的 CPU/自检是集成内部工作，发现问题后由集成修复，独立验收仍要求最终无未解决阻断。

中间静态审查与 CPU 节点验收的是检查工作是否实际完成、范围及对象版本是否完整、证据和问题是否可信。候选测试存在有定位的缺陷，可进入纠错；这不代表测试资产已通过。基础设施中断、工具缺失、未完成/漏查范围或对象版本不可确认不能伪装为完成。CPU 每个适用 case/调用必须有实际成功或具体失败证据，无关设备行为注明待设备验证，不把任意异常当作预期业务成功。

完整 build_tdd_cases.py 会准备缓存，首次调用前须按完整 CSV 安排 CPU 资源。输入配方无效等测试缺陷与检查基础设施不可用分别记录。纠错必须关闭阻断并提供最终完整校验与适用 CPU 通过证据，不能仅依赖中间节点 pass。

## 审查建议与缺陷关闭

在既有问题记录中分别说明缺陷事实及违反的原要求、修复后必须保留的行为，以及建议手段和适用依据；沿用原报告，不新增字段、格式或交付件。缺陷是否存在与某个建议是否可执行分别判断；没有现成方案不等于缺陷不存在，建议被拒绝也不等于问题已经关闭。

给出具体修改手段前，只读核对本次实际使用的公开测试契约、工具版本及相应参数/允许值、入口和写入权限；依据已有公开说明或适用接口定义，不因其他分组/阶段支持同名行为就推断当前入口兼容。引用已有证据，已知限制不留给纠错重复试错；无法确认的能力说明未知与所需依据，不作为已确认可执行的措施强制下发。需要修改冻结设计、外部工具或扩大授权的建议明确其负责阶段，不能当作当前纠错节点可直接执行的动作；审查仍只读，不为验证建议新增实验或越权运行测试。

纠错先确认原问题和必须保持的行为，再核对建议是否适用；在原契约允许范围内选择有依据的修复，不以照抄建议为完成标准。可以不采纳不适用的建议，但须说明限制及原问题如何处理；采用替代方案时，证据要支持原行为与判别力均保留。工具校验通过、另一个用例通过或写出未采纳理由，均不能单独证明缺陷已关闭。替代方案若改变冻结强制条款、接口或验收标准，按原阻塞交接规则处理，不能自行解释成等价或以包装规避固定工具。

验收者对照原要求、真实缺陷、实际改动及当前证据判断是否关闭，不因未按建议修改单独判失败，也不因建议不可执行就降低原标准。原缺陷已被证据排除或在允许自由度内修复时说明依据；仍未满足要求或无法解决的能力缺口保持未关闭，按既有节点标准裁决，不把“拒绝建议”写成“零问题”。

只调整建议及说明、测试资产和相关依据未变时，引用仍有效结果，不重跑全量缓存或 CPU。实际输入、Golden、断言或比较逻辑变化时沿现有失效边界补齐必要验证，完整校验与适用 CPU 证据要求不变；版本和限制未变的兼容性调查复用原记录，不在重试中重复尝试同一已知不支持的手段。

## 纠错、最终独立审查与恢复

本节的独立 fix/final、rollback_to 和 checkpoint 仅适用于已冻结的旧八节点图；新四节点图使用上文“四节点测试集成与恢复”的原生重试，不混用恢复方法。

纠错作者不代写最终审查；最终审查由 harness 派发只读角色，对最终版本及变更影响独立判断。实现、Golden、用例、参考或检查逻辑变化使证据失效时按影响实际重做，不刷新旧记录冒充通过；有效记录不重复计算。所有原始资料只存一份，节点证据索引引用实际路径、版本与判定依据。

最终验收失败时使用模板的原生 rollback_to 返回纠错，受顶层 max_rollbacks 限制。原生 checkpoint 可能恢复 test-generation 下的候选文件，所以每次最终原始审查报告放在 .workflow/reports/ 并通过原生失败反馈保留实际路径；纠错读取 advice/反馈处理当前恢复资产，不能依赖必然仍存在的失败候选文件。阶段内重试保持独立输出与版本核对，不重做已完成的准备。单独启动模板使用其顶层预算，嵌入主图时沿用主图预算，不增加私有循环。

## 权限与来源边界

不修改冻结 spec/DESIGN/Unit、用户 performance、目标实现或精度标准；纠错仅允许有业务依据地修正 Golden、测试准备和 whitebox/tdd/blackbox，保留 ID、失败证据与差异。CSV 和固定入口通过外部 Skill 的公开入口维护，不修改外部 Skill 或现场伪造固定工作流工具。所有报告遵循测试执行记录与验收报告约定；上游错误和权限缺口不通过越权改资产解决。

标准 .case_cache 为派生缓存，不进入源码或检视 Git 基线；真实测试数据和 Golden 仍冻结。缓存命中只复用参考计算，不免除逐例语义检查。CPU 结果、模型预测和脚本回归都不代替真实 NPU 精度或性能验收。
