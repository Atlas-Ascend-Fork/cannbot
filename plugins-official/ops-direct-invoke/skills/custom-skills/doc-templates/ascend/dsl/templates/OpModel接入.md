# OpModel wheel 接入与工作区

本工作流加载已安装的 ops-theoretical-performance-estimation，读取其 ops-opmodel-toolkit/SKILL.md 进入 OpModel 路径并使用公共 wheel 接口。父 skill 的纯 Vector Roofline 路径与 OpModel 分开，不能把 Roofline 时延下界、平台范围或阈值套到 OpModel 方案。Skill 提供方法、参考和可编辑示例，运行能力由选定 Python 环境中的 opmodel 包提供；不依赖源码 runtime Skill、私有 checkout 或在安装目录内写入模型。

## 环境与实际加载

仅在实际建模、模型搜索或校准前加载 toolkit 的安装/能力说明，以本轮已确认的 "$PYTHON" 核对实际包版本、公共入口及 accel_model、operators、hardware 的加载位置，排除其他 editable checkout 或项目同名包遮蔽。出现遮蔽时使用项目中的隔离模型执行目录和受控模块路径，保存实际命令与环境；设备执行仍沿用原环境，不全局改写其加载路径。缺少 wheel 或接口不兼容时记录缺口；安装/升级沿用已有环境授权，由负责环境准备的角色处理，不在节点内自动升级共享环境或切换到未经确认的源码环境。

模型执行必须使用独立子进程，工作目录位于 OPMODEL_WORKSPACE 或其隔离子目录；按该子进程设置模块路径，不能继承含生产包根目录的 PYTHONPATH，也不能仅换工作目录而保留冲突路径。所需用户模型/hooks 路径按公开契约显式提供，核对实际 operators/hardware/accel_model 均来自本次 wheel；设备执行的环境不因此全局改变。生产入口则核对实际加载文件属于本轮算子源码，不能误用 wheel 的同名包。

工作流默认生产入口使用 operators.<op>.<op>，而 wheel 也提供 operators 包。所需包标记或注册/构建元数据必须在 Unit 规划时纳入允许源码路径；只有命名空间目录而无包标记时，即使生产根目录在 PYTHONPATH 前端，也可能被后续的普通包覆盖。已有项目先确认包形态，按实际需要声明并实现，不强加无关文件；不能在实现阶段越过 Unit 写集临时补文件。生产包与模型包分别在各自进程验证，不把加上包标记当作模型侧隔离已解决。

从已安装的 ops-theoretical-performance-estimation 定位其 ops-opmodel-toolkit 子目录，将该子目录的绝对路径设为 OPMODEL_SKILL_DIR；不能将父 skill 根目录作为模型参考根目录。OPMODEL_WORKSPACE 指向本轮用户目录，设计默认使用 $WORK_DIR/design/model，优化使用 $WORK_DIR/opt/model，按当前阶段设置并在其中或其隔离子目录运行。完整 case 输出不在系统 /tmp 下，搜索会话位于 OPMODEL_WORKSPACE 内；Skill 和 wheel 安装目录保持只读。没有模型工作时不强制这些变量或依赖就绪。

## 方法与公开契约

加载已安装的父 skill 并读取 ops-opmodel-toolkit/SKILL.md，按当前任务选择子目录中的工作流和参考资料。无需客户端将子目录单独发现为 skill，不单独注册同名入口。以下路径相对 OPMODEL_SKILL_DIR；以实际安装的 skill 和 wheel 接口为依据，核对版本及能力，不要求每个节点通读全部参考：

- 新算子/模型接入：references/new-operator.md；模型语义、规格与运行说明按当前交付契约保存在用户模型中，不替代冻结的算子 spec.yaml。
- 性能评估：references/perf-eval.md；分别报告完整输入、逐核工作量与结果 scope。
- 配置及结构搜索：references/agent-dag-opt.md、references/agent-dag-opt/search-integration.md 与 references/agent-dag-opt/evidence.md；按安装版本选公开入口，比较与覆盖沿下文边界，不把登记、单点或 Top-K 当成实际搜索覆盖。
- 联合优化：references/joint-optimization/guide.md 和 workflow.md；任务只消费当前授权阶段，模型优化与实现采用分别验收。
- 空泡与数据流：references/dag-bubble-opt.md、references/dag-dataflow-graph.md；区分声明连接、实际执行与合法跳过，不以 trace 展示顺序单独判定依赖合法性。
- 设计落稿：references/opmodel-design-gen.md 与 assets/templates/design.md；承接固定承诺、受约束选择和真正待补项，保留完整执行算法及适用边界，不要求提前写完整生产代码。
- 硬件准备与搬运：references/hardware-preparation.md、references/framework/transfer-contracts.md；按需核对目标、保存配置、源/目的访问与计费量、有效布局及释放边界，不从示例或路由名称推定能力。 实际分析搬运工作量或空泡时区分逻辑字节、实际读写、物理容量、命令与内部服务单元，不把服务单元当作额外命令，不将重叠服务与等待相加为总耗时。
- 显式 Vec/VF 计划：references/framework/vec-plans.md；仅在实际采用该入口时核对其单区域、未分片且无预建存储/控制/发射协议的基线限制，以及当前 wheel 的实际支持；搜索覆盖按下文处理，不强制所有模型使用 Vec 搜索。
- 已有编译反馈：references/framework/compile-feedback.md；关联真实候选、源码与构建身份。编译、资源检查、正确性或计时失败也保留实际退出码、原始日志及已生成报告，缺失工件如实保留；失效的旧编译或设备证据不能回填失败候选。仅消费本阶段已有或原授权范围内的结果，不因该参考新增编译或设备实验。
- 目标、重评分与结果复用：references/framework/objectives.md；沿用调用方目标与修订，完整方案排名/并列、逐 case 周期诊断、资格和设备收益分别记录，目标分数不换算成加速比。

候选定义、case 和搜索配置保存在用户模型中，通过公开 YAML/hooks、示例脚本或 wheel 入口运行，不依赖源码运行时的私有路径。各入口的硬件覆盖能力分别核对；新建模型按 references/hardware-preparation.md 从已确认的目标 SKU、环境和来源保存明确 hardware 引用，独立评估及接续搜索沿用保存的内容身份，只有任务明确覆盖时才变更并重评受影响比较。不假定 resolve_eval_hardware 或其他入口会自动保留该引用：以实际 wheel 核对解析结果和生效机制；不一致时仅使用当前公开入口支持的显式覆盖并确认生效，否则记录能力缺口，不静默切换普通、streaming 或 detailed 变体，不因本机设备或文档示例改选。按本任务冻结的代表集/阶段评价范围复评，toolkit 的完整 case 不等于强制全部用户 case 仿真；全部用户 case 的轻量覆盖和完整容量资格沿原任务保留。

硬件 profile 必须对应目标 SKU 和本次入口实际加载的核数、时钟、容量与成本。需要覆盖或新增 profile 时按 toolkit 当前支持入口与原始物理来源进行；不假定统一 --hardware 参数，不把教程的假设 profile 当成目标设备事实。能力不支持或成本未知时明确局限，不能借丢依赖、零成本或不一致硬件取得有效排名。

本工作流设计交付仍为 design/doc/DESIGN.md 单文件。toolkit 的多实现模板总览、各模板完整设计与逐 case 映射合入现有稳定章节/branch ID：共享算法、数据通路、存储及同步规则的 case 共用正文，真正结构不同的方案分别完整展开并关联总览，不按模型分组、case 数量或参数实例复制设计或强制拆 Kernel。沿 selection、完整输入清单和已有轻量覆盖记录关联每个原 case 的适用路径、有效参数/边界与实际证据状态；未仿真或未验证者如实标记，不补造预测，不把逐 case 赢家拼成运行时分派。昂贵探索仍由代表集承担，缺口驱动扩充；该映射不新增全 case 仿真、固定表格、selection/Unit 字段、独立总览文件或 designs/ 子目录义务。性能阶段已有的算子、源码和设备范围仍由性能契约决定。

模型交付核对 toolkit 要求的 SEMANTICS.md、SPEC.md、README.md 及相对引用，候选导出不自动代表这些文件齐全；已有同一身份的有效文件可复用。它们服务模型语义和运行复现，不另建一套算子公开需求、数值判据或设计承诺。设计期同一执行者在同一会话完成建模与落稿，沿原 selection 字段引用模型、成本与复现证据，不新增 selection 字段或业务台账。

VF 缺匹配实测时，可按 references/framework/vf-costs.md 形成有依据的估算，保留公式/单位、实现绑定、硬件/dtype/工作量适用域、分块、来源和不确定性，明确标为“Agent 未实测估算”，用于授权范围内的探索，不冒充校准或设备资格。真正无法形成可解释成本的未知项仍不补零、不进入有效排名。匹配实测到位或成本身份变化后，只更新受影响成本并重评必要结果；不要求为读取新 skill 自动升级 wheel、安装预测器或启动设备采样。

设计交接以新模板的固定承诺、受约束选择和真正待补项区分责任，缺少具体地址/API/事件编号不自动阻断已有能力依据的受约束选择；关键能力或依赖未闭合仍按本任务阻断，不能用“部分可实现”绕过当前任务完整交付要求。模型参考、实现精度参考、执行数值回放及设备验证分别标明，语言无关执行算法仍完整覆盖实际计算、全部存储的生产/消费/复用及必要边界。

## 模型比较与搜索边界

局部搜索周期与完整 case 周期分别记录。要报告完整模型收益，先应用候选并重新加载完整模型，在既定评价 case 范围内按相同真实输入、硬件、成本口径及缓存假设复评；有效的同身份结果可复用。沿已有原始记录核对实际生效的 tile、核数、切分/映射、slots/phases 与候选改变项，不能仅抄请求参数或候选名。局部结果只支持局部结论，不能与完整 case 周期计算加速比；完整 case 指一个真实业务输入，不等于全部用户 case。

使用显式 Vec/VF 搜索时，以当前 wheel 实际返回的候选状态、ledger/complete 判断覆盖；非法/超容候选的失败及消耗按该入口的原预算口径保留，不将模型内部评价次数直接等同于工作流完整候选数。完整枚举结束但全无合法结果，不代表已有合格赢家；首项失败也不能单独证明后续未评估。若实际提前退出，先核对包版本、异常、预算和已有记录，再按原权限决定恢复或报告缺口，不自动重跑整批或假定文档描述已被当前包实现。

执行、自检与独立验收使用上述同一边界，只有实际涉及的入口和结论才核对；沿既有代表集、阶段范围、预算及记录处理，不新增字段、台账、固定表格、全 case 仿真或设备实验。

## 分层筛选与评价范围

模型路线按轻量过滤、分层粗筛、缺口补筛和入围精评组织评价；这是节点内安排，不新增工作流节点或字段。沿既有计划/搜索记录，在各批评分前说明候选与 case 范围、子集评分和保留规则、原预算及停止条件，保留实际结果和限制。不固定粗筛 case 数、比例或入围 Top-K，也不默认全部候选先跑完整代表集；有耦合的参数、映射和结构选择仍作为完整配置评价。

轻量过滤复用已有公开派生及资格证据，已证实违反语义、容量或依赖约束的配置可提前排除；评价等价仍沿原身份、生效配置及行为依据判断，不凭分数相近、周期相同或静态上界超限合并或淘汰。模型执行失败、成本未知或证据不足沿原规则保留未决，不伪装成性能差，也不进入有效排名，不为过滤另加完整仿真或设备实验。

粗筛集从当前完整代表集中选取，先覆盖可能改变配置偏好的成本路径、任务几何、资源或调度行为，再优先使用已有记录或有依据估算中成本较低的 case；不只挑最便宜输入，不机械按原始参数枚举。粗筛仍使用原 case 的完整业务输入与同口径单例评价，不缩减 shape、任务或评价 scope 冒充覆盖；昂贵 case 承担无法由其他场景解释的关键行为时，不能仅因耗时而跳过。纳入同批粗筛的有效候选按同一粗筛集及已说明的评分口径比较，保留原目标和权重，不将子集分数当作完整代表集或全组成绩。

保留综合表现有竞争力、在某类已评场景有明确优势，以及在当前评价范围内现有依据不能可靠区分的候选；不机械截取少数领先名次，不发明不确定性阈值。粗筛未入围只表示该阶段的筛选结果，不证明完整代表集性能差或资格不合格，原配置及评价依据仍可追溯。影响筛选的机制缺口、场景优势或排序差异无法解释时，从原代表集中补入能区分相关候选且成本适用的 case；更新同批评价范围，复核受影响候选是否恢复，配齐必要比较后再决定入围。粗筛集内补筛与完整代表集扩充分开，后者仍须满足原有缺口要求和执行侧预算管理规则，不默认整批全交叉重跑。

精评覆盖入围候选与完整当前代表集及必要补证场景，复用身份匹配或有据等价的粗筛/补筛结果，只补缺失、失效组合，再按完整范围重算评分、退化和排名；不同阶段或覆盖范围的分数不混排，也不因阶段标签不同强制重跑有效单例。全组轻量适用性、完整容量及成本资格仍按原要求核对，不能用粗筛或精评数值通过豁免；最终采用方案的导出、实际加载、配置恢复与回读沿原契约，不用搜索结果冒充回读证据。

执行者先在适用预算中核对必要精评、资格补证和赢家回读所需空间，再确定粗筛及补筛范围；沿下节的原单位预留/结算和停止规则，不设固定预算比例。区分自行制定的计划与用户明确的资源、时限和授权上限；前者确需调整时沿既有记录如实说明理由、时机、实际消耗与未完成项，不重置历史消耗或冒充预先计划，后者不得自行放宽。必要比较或资格无法完成时如实交接未完成，不以局部分数或缩减标准凑交付。已有结果足以精评或规模很小时，可有据合并评价阶段，不为步骤形式新增运行；验收按实际阶段及证据判断，不因未执行独立粗筛而单独拒收。没有充分依据时不声称与全交叉赢家一致、全组达标或全局最优。

## 有界并行与统一汇总

本节仅组织节点内的离线模型评价，不把搜索改成固定网格。多个已确定、互不依赖的配置且资源允许时，执行适配默认采用有界并行，每个配置内部按该评价阶段的 case 范围顺序执行；基线建立、依赖前轮结果的候选生成、代表集扩充后的必要补评及赢家导出后的回读保留原先后关系。不得据此并行开展 VF 设备实验或性能计时。

并发数依据主机可用 CPU 配额、内存预算、已有峰值依据及入口内部并发确定，不固定取值、不按主机核数直接开满，也不改变模型目标硬件核数。同一节点各组共用模型进程额度；harness 的 max_parallel 管理节点并发，不能代替该额度。资源或隔离依据不足时串行并说明限制，不要求独占主机，不为采用并行追加资源摸底实验或改变环境。执行范围、并发依据和必要串行原因沿既有计划、搜索证据与日志记录，不新增字段或独立台账。

先核对当前版本公开入口是否支持所需并发；支持时复用其能力，否则由本轮允许的模型执行适配组织有界子进程池，不假设存在未公开的并发参数，不修改 wheel、harness 或新增固定工作流脚本。模型仿真保持进程隔离，协调层可并发管理子进程，不将仿真本体改为共享进程内线程执行。模型、硬件、成本及 case 输入在本批执行期间保持只读；实际执行任务按阶段、组、配置、case 及尝试身份隔离输出，重试保留失败记录并使用独立输出位置，不覆盖其他任务或清空原始结果。

共享汇总、排名及预算记录由执行适配的协调进程统一更新，工作进程不并发改写共享模型、会话或汇总。沿原执行日志保留实际命令、任务身份、起止和退出结果及原始产物；协调进程确认必需结果有效后再归并，按既定阶段、组、候选、case 及单次评价身份核对缺失、重复和未知组合；尝试记录不增加覆盖次数或 case 权重，同一逻辑组合的最终贡献按原有效结果或多次采样规则确定，不自行取最快或最后返回结果。完整共享结果通过原子替换发布，不能以最后一个进程写出的局部文件冒充全量。进程退出成功、文件存在或周期数较小均不单独证明结果有效。

完整性沿“分层筛选与评价范围”核对：粗筛/补筛为本批纳入候选与对应子集，精评为入围候选与完整当前代表集及必要补证场景，不把两者混成所有候选与完整代表集的默认全交叉，也不扩成全部用户 case 的仿真。必要比较结果及其生效配置、评价范围和身份须齐全；执行失败、预算未覆盖、已证实不合格及其他未决项沿原记录区分，不计零、不隐藏、不用先完成子集计算完整分数。共同资格已证实不成立的候选仍可按原规则淘汰，无须补齐其余组合；有据等价复用、全组轻量覆盖、完整资格和最终配置回读规则均保留。

执行侧由协调进程分别核对节点并发额度与原组/阶段预算，共用进程池不授权互借预算。以下派发、预留、结算与停止要求用于执行管理；自行计划确需调整时按前述规则保留事实，用户明确的资源和授权限制始终有效。派发前按原计量单位、累计范围及既有时限，核对已结算消耗、未结算在途预留和本次新增需求不超过适用预算；配置任务包含多次 case 评价时沿原单位换算，不能用 worker 数代替评价次数，也不擅改按候选计数的口径。完成后按原规则结算，释放未使用预留；原规则应计入的失败、重试消耗不得抹去，不自行重置或另开预算。完成先后不得改变候选选择、输入与种子、case 权重或评分口径；依赖结果的下一轮须经过原决策边界，不以先完成的较快候选替换既定比较。预算或停止条件触发后停止派发，按原时限回收本次在途任务；只能处理身份已确认属于本次执行的进程，保留超时、中断及未完成事实，不遗留无法确认的后台工作后声称完成。

恢复按单个候选与 case 核对模型、请求/生效配置、真实输入、硬件、成本、版本、该次评价的 scope 及原始结果；普通缓存须完整、有效且身份匹配，有据等价候选沿原等价规则及逐 case 关联引用原始结果，不强迫各别名独立运行或另建目录。单次评价范围与整批代表集比较范围分别判断：代表集扩充时，原单例条件未变且结果仍有效的组合继续复用，只补缺失或失效部分，再按当前完整比较范围重算汇总和排名，不沿用旧范围分数，也不默认整批缓存失效。不凭 summary 文件存在或事后补哈希复用旧结果；搜索结果不能冒充导出配置的实际加载与回读证据。预算预留、结算、停止及自行计划调整由执行者负责；验收者依实际运行记录独立核对用户明确的资源与授权限制、实际隔离、汇总和必要比较完整性，不因自行设定预算超支或调整单独拒收，也不要求事后补造预留、提高上限或重跑来消除历史超支。预算不足造成必要比较、资格或最终回读缺失时，按实际交付缺口判断，不替执行者重跑；有依据的串行、未采用固定并发数或未另造并发报告不单独构成拒收理由，不追加并发证明实验。

自检与独立验收统一按交付质量判断：模型符合既定目标及必要性能、结构约束，必要比较同口径且可信，全组适用性与完整容量资格成立，最终配置按要求实际加载回读，关键引用可追溯，结论不超出证据。执行者提交前回读实际交付与关键原始依据，不能仅凭校验脚本通过认定全部完成；归档、清理或修订后核对受影响的引用及结论。验收者独立检查同一标准，不另设预算补账、固定表格或全量重跑义务；必要证据缺失、影响结论的未解释矛盾及用户限制越界仍不能放行。

设计节点的模型阶段先完成必要比较、全组资格及最终配置回读自检，再直接承接实际采用方案落稿，不另开落稿执行会话，不把自检当作独立验收。已有执行报告及时保留当前方案、关键原始证据位置、未完成项和下一步；原生重试可能新建会话，恢复按实际产物和身份只补缺失或失效部分，不默认重跑建模。落稿发现实质结构或成本变化时按影响同步模型、selection、设计及必要结果，外部冻结输入与用户资源/授权限制不变。
