# 设计落稿的关键规则核对

本方法用于方案落稿及其独立验收，帮助在扩写前消除关键规则矛盾。DESIGN.md 仍是唯一设计交付件；不新增设计台账、审批阶段、固定表格格式或调度步骤，内容要求由本任务按路线选定的落稿 Skill 承接，不额外套用其他设计 Skill 的整套模板或流程。只处理本算子适用的计算与执行结构，不为简单串行算子套用流水模板。

## 性能导向与候选形成

除非用户另有明确取舍，初始方案在语义、精度、完整支持域和资源约束内以性能为目标；不接入后续实测迭代调优或未设加速比门槛，不等于只需正确与容量可行。有性能 case 时仍用于设计评价，模型路线按既有目标、权重、代表集和预算形成可比较的成本目标，不将自行选择的评分办法写成用户要求；无 case 时沿范式与成本依据作性能判断，不因此启动模型路线或虚构预测。

扩大参数搜索前，结合算子实际语义、工作量、数据搬运和并行方式判断主要成本及可改变它的关键选择。已有明显的语义复用或结构改进机会时，沿现有设计/搜索记录说明采用或排除的依据，不能先固定数据流、再仅凭不改变主要成本的 tile 参数赢家宣称已完成结构选型。数值相等、逻辑共享和物理别名分别判断；减少搬运或复用数据须核对表示、生命周期、容量及同步，独立入参或不同地址本身不构成排除数值复用的理由。依据已有可靠推导、模型或适用参考即可排除无竞争力或不可行的路线；只对仍有必要区分的候选在现有授权与预算内评价，不要求穷举算法、固定候选数量、全 case 仿真或新增设备实验，也不强制特定算法或复用方式。

执行者自检和独立验收共用此边界：确认选型目标、主要成本、相关候选取舍与最终方案一致，必要性能和结构承诺可交实现落实；固定结构内的参数比较不冒充全局最优。合理取舍可以保留原方案，但不能只以“能算对”“装得下”或“不接入调优”代替性能依据。沿既有报告引用有效证据，不新增表格、字段或交付件；验收不替作者搜索或补实验，不把未授权的实测目标、未执行的设备收益或未经证明的全局最优作为门槛。

## 先确定规则，再展开说明

消费已验收的 spec、需求、环境和性能 case，先区分性能评价范围与完整规格支持域：前者决定模型搜索、比较和预测的范围，后者决定必须交付的实现方案。未建模的合法输入不要求全量仿真，但仍须由参数化规则或有依据的默认路径明确计算、资源及边界处理，并安排可落实验证；不能仅写“实现时补证”来填补尚无设计的路径，或把模型断言、参考样例范围变成公开支持域限制。无性能 case 时不要求模型或搜索。定位必要输入后即在 DESIGN.md 落盘适用章节及已确定规则，分批补齐 soc-info 和最终参数，不等整份长文一次性输出；扩读对应具体缺口，每批确认实际落盘，恢复从真实缺项继续，不设字数、调用次数或新脚本门槛，骨架不算完成。

- **数值链**：从输入到输出固定计算/累加精度、运算与舍入/夹取/转换顺序、状态更新和写回含义；沿真实分块、过滤/掩码和任务分发核对局部有效性、危险运算之前的处理以及贡献的初始化、合并和结束。整体有贡献不证明每个局部算式有定义，后续屏蔽或乘零不能消除已发生的 NaN、越界或非法运算；合法特殊值不能作为空贡献吞掉，原规格的边界、异常传播和完整支持域不得缩减。设计自行采用非平凡改写或具体转换组合时，依据适用推导、接口语义或已有有效证据确认适用域内的值、位表示及误差满足冻结契约；区分数值转换、舍入/饱和和位重解释，不能由 API 支持某类型、容量可行或模型退出成功推导组合等价。必要示例须服从同一规则，不能与公式或特殊值语义矛盾。主参考及容差沿冻结规格，不因同精度、高精度或输出 dtype 擅自改变；只核对当前方案涉及的规则，不要求穷举状态、全量数值仿真或新增设备实验。
- **调度链**：扩大昂贵搜索或长文展开前，先沿当前候选明确输入到任务、块内到全局位置及实际消费范围的关键映射，再核对动作的执行主体、前置条件、搬运与同步依赖；以参数规则及能改变行为的边界作轻量代入或静态核对，不能仅因现有性能 case 成立就外推合法域。接入和必要建模可用于确定关系，不要求先选最终参数或增加全域实验；候选改变关键关系后先更新定义再继续比较。存在流水时从同一阶段/索引关系推导启动、稳态、排空及小块情形，表格与伪代码不各定时序；无流水按真实依赖，不强加阶段数。
- **缓冲链**：从逻辑对象映射到真实物理分配或别名，再沿生产、全部消费者最后读取、释放及下一次覆盖，推导槽数/代次、字节数和容量结论；独立分配与别名不能在不同章节切换口径，不能只用槽号取模或容量表证明生命周期安全。共享物理存储只计实际分配，但别名成立须有字节范围、时序及消费依赖依据，不能凭计划复用扣减。调度与分配共同决定同时在役版本和峰值，互斥路径不机械相加。模型采用抽象名称或粒度时可用现有章节/证据给出映射和静态证明，不强制新增模型字段或工具同名表达，也不能以抽象掩盖影响资格、成本或同步的真实差异。 完整支持域的容量证明沿既有配置与资源定义核对：每个合法输入经真实分发条件进入一个适用配置，该配置的资源需求在相应可用容量内；无需一个配置包办全域。固定分配可直接核对，参数化分配按有依据的取值上界核对，有限分支及切换边界分别证明；若输入维度只改变任务数而不改变分配，应由实际公式说明。不假定最大形状总是最坏情况，或形状/tile 更小就必然安全。需求须包含适用的临时量、分片/复制、槽数及对齐，按最重实例或真实共享域比较；别名/错峰/复用仍有生命周期依据，不能从性能 case 成功外推域内全部输入。可靠上界满足容量即可，不要求全输入枚举或全 case 仿真；上界超限只表示该证明不足，应细化需求或在设计权限内调整配置后复核关系，不直接认定实际超容或缩小支持域。默认/回退配置同样给出规则及证明，变化联查计算、布局、同步与生命周期，影响选型资格或成本时按原规则处理，不因未建模而虚构性能保证。无法闭合时报告设计缺口，不留给实现临时决定；未到期编译/设备补证仍按原时机验证，不新增字段、表格或脚本。

公开行为沿冻结规格确定：合法域、调用方前提、明确要求的负向/域外行为及 Host 处理须对同一调用给出一致结果。参考实现的域外防御不自动成为公开保证；冻结规格本身有冲突时按原协议交回，不自行删改。影响当前设计含义的矛盾在交接前解决，未到期的可行性补证按其责任与时机保留，不将两者都写成泛泛的“待确认”。

涉及尾块、对齐、填充或中转时，在现有适用章节区分分配容量（含布局、步长及生命周期）、搬运/加载/存储的实际访问范围、计算/归约/状态更新/写回的有效消费范围。沿实际消费者核对这些范围及无效位置的影响，不从分配了完整 tile 推定必须计算整块，也不从有效计算范围较小推定物理访问合法。有效视图须保留真实父布局与 pitch，视图重解释不执行数据重排。仅核对本方案涉及的关键路径，不新增固定表格、字段或全缓冲台账。

补零、屏蔽、写满 tile 或中转成为强制承诺前，说明原规格、实际接口/访问限制、无效数据影响有效结果的消费依赖，或明确选定的性能/调度策略及其适用条件。接口、布局转换或数据组织确实需要的中转应保留；未参与有效消费的位置不因预留容量就自动要求初始化。归约尾部、跨元素操作、槽位残留及对齐访问仍按真实路径保证合法与正确，不统一规定不补零或直接搬运。保守处理和示例写法不能自动升级为唯一机制；也不因数值等价否定有依据的结构承诺。不要求穷举替代路线或新增设备实验。

模型路线的执行者落稿时复用本任务仍有效的建模结果，核对本设计采用的载入位置、阶段、槽数和参数规则与 selection 引用资产相符，不为落稿形式重复建模检查或重跑搜索；最终独立验收仍联合检查模型交付质量与设计承接，不能将阶段自检视为已完成的独立验收。使用中发现本任务模型选择与设计不兼容时，按本任务权限及实际影响修复并同步 selection、模型与设计；不得改动冻结的外部输入，超出权限或必要依据无法闭合时按原阻塞规则终止。

建模与落稿在同一次执行会话内连续完成，不另派执行者；模型阶段自检只确认模型评价及其全组资格责任，不能冒充完整 DESIGN 自检或独立验收。提交前分别核对模型评价证据与最终设计，各自负责范围沿同一质量标准验收，最终一次独立验收联合覆盖两者。上下文压缩或原生重试后，先读实际交付、反馈及已有报告中的当前方案、证据位置、缺项和下一步，再按需恢复，不承诺跨重试保持会话，不新增恢复文件或台账。

流水资源份数由阶段偏移及每个资源的生产、全部消费、覆写时序推导，在 DESIGN.md 的所属规则位置维护唯一表及来源；其它槽深、轮转取模、编译配置、别名和字节预算引用同一推导。新增、合并或调整阶段时按同一推导重新核对全部资源并重算受影响份数，不直接沿用旧阶段划分的份数；无流水时按真实生命周期核算，不强加流水。执行阶段自检和最终独立验收均按这一关系联查推导与全部必要展开，不能仅检索字面量。

## 一条规则，一个定义位置

每条关键规则明确权威定义及适用版本：设计决策在 DESIGN.md 的所属稳定章节/锚点维护，模型参数、派生量及实际生效行为引用对应原生定义并说明设计映射，不在文档中另造一套值。保留所选 Skill 要求的模型交付文件及必要镜像/展开；必须展开的内容标明同一来源并同步核对，不能因精简删去接口、完整算法、分配或关键性能与结构承诺。数值链、调度、生命周期和容量的其余说明、表格、伪代码与示例引用该定义；展开仍须正确，“示意”不豁免矛盾。

关键参数及派生量沿权威定义和真实输入核对，分块、槽数/索引、任务分配与有效/物理范围不多处独立推导。case 数值、模型排名、分配结果和证据状态引用当前原始记录，只在正文保留影响方案判断的摘要，不逐 case 抄写另一套完整结果表；必要的 case 归属、选择规则、覆盖关系和限制仍须可追溯。硬件事实保留在 soc-info.yaml，设计分配在所属规则位置维护，公开语义引用 spec；不抄成长规格、环境或 API 附录。

关键计算、数据流和事件关系优先用语言无关表达；设计固定数值含义、有效访问/消费、归约/广播、资源和同步关系及能力依据。普通 API、指令组合、循环/索引、地址和事件编号由实现者在允许范围选择，不为填满能力表提前设计绕行或把示例升级为强制机制。选型实际依赖的计算分块、搬运路径、流水重叠、缓冲复用以及数值/存储表示必须保留；若设计确需固定具体机制，其适用接口与组合后的数值、表示和消费语义均须成立，不能只核对名称、签名或单步可用性。语言无关数值契约必须在本阶段自洽，已知错误或必要关系不明不能标为“实现时验证”继续交付；仅编译/设备可判定的可行性沿既有首次消费前义务处理，不提前要求设备结果。

## 验证安排必须能区分目标行为与错误

设计定义需要保证的行为、原规则来源、可观察性或适用证据方式及完成时机；Unit 负责能力归属、阶段范围和可落实的义务，测试负责具体输入、配方、Case ID 与断言。沿已有章节和验证矩阵引用规则，不为每项承诺在三层重复生成完整用例和错误变体清单，不新增字段、表格或交付件。

可由公开调用和结果判断的行为说明观察目标；依赖源码、编译产物或运行时结构的承诺说明相应证据与到期时机，不能只凭普通数值通过认定覆盖。尚需组合编译/设备结果的项按既有补证义务安排，不提前要求通过；已知矛盾、不可验证的当前承诺或缺少可落实安排仍须在本阶段处理。

设计确已给出具体输入或事件场景时，独立核对其前置条件、实际派生量、观察结果、判别依据及范围；示例不能豁免错误，也不因有示例就把其取值变为唯一构造条件。无完整输入时以原规则和适用依据说明验证方式，不补造 Case 或未来结果。真实测试例化仍须在对应阶段证明实际触发与判别力，不能用职责分工免除原要求。

## 提交与独立验收

提交前确认当前输入与送审对象身份后，先核对最终 DESIGN 的关键语义：沿冻结规格检查计算链、非平凡改写/转换组合、特殊值及必要示例，确保实际方案保持所要求的值、表示与误差边界；再联查完整支持域的配置分发、有效计算/访问、物理分配/别名、生命周期、槽数、同步和资源上界；最后核对模型评价及全组资格、配置回读、原始排名/结果、引用、场景摘要与复现入口对应同一最终版本。两条路线均按“性能导向与候选形成”保留性能取舍，模型阶段自检不替代最终设计自检，不以模型资格自动证明设计语义；适用原始证据仍可共用。可靠静态/上界及已有有效推导、接口语义和原始证据优先复用；仅有具体疑点且确需反例时做限定范围的 CPU 核对，忠实表达被选计算链，不新增脚本要求、固定输入集合、完整 Golden、全 case 仿真或设备实验。

在既有执行报告简要索引关键规则、核对范围与依据及未关闭项，区分已经证明、普通实现选择和未到期可行性补证。文件/字段存在、容量表、脚本 PASS 或模型成功只证明各自范围，不得据此声明数值链或完整设计已通过；不另写一套全量报告。当前数值语义、资源或关键能力阻断未关闭不得交接，普通 API 选择未定不单独构成缺口，未到期编译/设备结果不提前要求。

首次独立验收确认当前输入与送审对象身份后，从冻结规格与实际 DESIGN 出发，按同一自检顺序先核对完整关键语义及其组合等价/误差依据，再审支持域、资源、同步和性能结构取舍，最后联查最终 selection、原始模型/资格/回读及交付身份；范式路线不要求模型证据。验收依据实际规则与原始证据，不把执行者自检、单步 API 支持、模型成功或文件齐全当作语义已成立；只审现有证据，不替作者搜索、重跑模型或新增实验。发现阻断后继续收齐不依赖该问题的轻量静态检查，受阻项注明范围和原因，不强制继续昂贵检查；首次不能只查形式而笼统认定完整语义通过。返工优先关闭原问题和关联影响，再补此前未检查项；既有有效结果按原边界复用，未证明、失效或相互矛盾的要求仍阻断，不要求全输入枚举、全 case 仿真或未到期设备结果。

## 返工的变更摘要与按差异复核

### 执行者保留可比较版本

首次送审时，在本节点既有报告目录保存可读取的 DESIGN.md、soc-info.yaml 送审快照及版本依据，执行报告引用实际路径。后续修改前保留与上一份验收报告对应的版本；相同内容可引用已有快照，不逐轮重复复制。快照仅用于比较与审计，当前 DESIGN.md 仍是唯一设计真源，不新增业务台账、版本协议或审批产物。

重试先读反馈、实际文件与有效报告，先修正权威定义并区分表达修正和方案变化，再追踪受影响的模型原生定义/必要镜像、配置、设计展开、场景摘要、资格/排名、复现入口与证据状态；按实际关联同步，不机械填写全部类别。不能只修验收点名的句子或用关键词清零代替关联核对。语言/API 替换按值、表示、误差、有效范围和消费语义判断，不从名称/签名近似认定等价；分块、动作次数、分配/别名、槽数或同步变化沿实际影响重评。按证据类别判断失效；原模型评价条件、行为及成本仍有效时引用已有结果，数值链修正不使无关模型结果自动失效，只有失效或缺失部分补证，不逐轮重写全文或重跑整个搜索；未知值不作为最终承诺。

摘要保留实际比较版本、问题处置、变化性质与理由、修改规则及关联章节、失效证据与补齐结果、仍有效证据的复用依据；原始记录不抄写。仅报告变化时明确未改设计，过程不追加进 DESIGN.md。方案变化使本任务选定模型的关键结构不再相符时，按影响同步模型、selection、设计及失效证据，必要时在授权范围局部重评，不默认重跑整个搜索；超出权限或必要依据无法闭合时记录具体不兼容并停止，不能仅标注未建模而继续声称承接赢家，或将已知矛盾留给 Unit。

上一版内容无法取得、版本与原验收对象不符或没有相应验收依据时，说明缺口，不凭当前文件补造历史版本或宣称已有结论可继承。

### 验收者独立划定范围

先确认当前送审版本和比较基线确实对应原始执行/验收报告，再读取实际文件差异及新旧证据；执行者的变更摘要只是定位线索，不能决定验收边界。分别处理未关闭问题、本轮修改、关联影响和此前未检查项，在本轮报告中说明复核范围及其理由。

原验收报告明确检查、原始依据足以支持该项结论，且当前内容/依据未变又不受修改影响时，可以引用具体项与证据；只有“通过”字样、API 类型表或模型成功记录，不足以继承组合数值语义已通过。整体 FAIL 不自动否定有效通过项，未检查、证据不足及失败项不能继承。发现此前结论被实际证据否定时明确标为失效并纠正，不为减少重试继续沿用；执行者宣称已修复仍须独立核对。

验收者从实际差异和共同定义独立区分表达修正与方案变化，追踪生产/消费范围、分块及动作次数、资源/生命周期、同步/复用、容量/模型对应和验证安排；不是所有修改都检查全部类别，作者列出的范围也不是边界。表达修正确认语义未变；方案变化须核对完整关联，局部问题关闭不代表方案仍成立。改变载入时刻需联查最后读取/覆盖、槽代次、在役数量及容量；改变分块主体需联查实际参数、计算/搬运次数与模型结论；改变数值判据、局部贡献表示或合并顺序时联查状态、边界、输出及验证依据；若同时改变状态归属或计算依赖，还须核对资源、同步及成本的实际影响，仅补失效证据，不默认重跑有效模型。文本未改但依据已变的部分仍须复核；设计与最终模型关键结构不兼容且未同步修复，或所需变更超出权限时仍阻断。已有有效验证不重跑，不替执行者补证，不因缺少重复示例、长附录或同一事实的第二份表格拒收，也不以减少重复放松完整语义审查。

无法可靠确认比较基线、旧结论或影响边界时，补齐缺口并扩大到必要范围；整体结构或关键规则广泛变化时按实际需要重新全面审查。不因轮次变化默认重审全文，也不按固定抽查比例跳过应检项。内容无变化且证据有效、仅报告解释不足时核对补充说明；规则或证据已变时仍需实际复核。最终原任务要求须由本轮复核与明确有效的历史结论共同覆盖，任何未关闭阻断均维持 FAIL；执行预算仍由执行者管理，用户明确的资源与授权限制不变；节点重试和调度由 harness 管理。
