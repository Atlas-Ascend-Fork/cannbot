# 黑盒用例设计（直调工程）

以已确认规格为输入（形式不限：需求文档、算子规格说明、参考实现或既有 golden 均可）。核对 spec 的约束、分派路径、数值范围，补充真正的覆盖缺口；不把已有用例反向当作全部需求，也不盲目展开参数笛卡尔积。

## 覆盖维度

| 维度 | 设计要点 |
|------|----------|
| 接口 | 参数次序、attrs 默认值、optional、输入输出数与 dtype |
| shape | rank、相等/不等约束、最小值、对齐与非对齐、典型规模、分派边界 |
| 数值 | 需求范围内的极值、零、最值、确定性梯度、随机（固定种子） |
| 分派 | 算子内部互斥路径逐条覆盖，含边界触发条件 |
| 边缘 | 边缘/边界元素的 replicate/clip/特殊权重等"魔鬼细节"用例显式触发 |
| 交互 | 对会影响结果的跨参数依赖做代表组合，避免无依据的全组合 |
| 异常 | 只测试规格定义的拒绝行为（constraint 违反、dtype/ndim/range 越界），正常边界与非法输入分开 |

L0 标记快速代表集（门槛冒烟），L1 标记常规功能组合（含大 shape 同分支论证走 code_review），L2 标记边界或异常（host 参数校验拒绝）。它们是测试设计标签，写在 `note` 和覆盖矩阵中。

每个新增 case 保留唯一整数 ID、输入参数、预期语义和覆盖目的。需求中的不适用值域不强加——例如数学定义不接受的负数不塞进正常精度用例。空 tensor 与 rank=0 标量是不同语义；是否支持依据需求，而非自动都加进范围。

## Golden / 参考实现

- 已有独立参考实现（golden）时：直接复用，不重新实现、不复制、不篡改；加载方式保持只读，方案记录其来源与版本。golden 应独立于被测 kernel（如 numpy 实现），已与权威实现交叉验证一致时直接复用并声明来源。
- 无既有 golden 时：按已确认规格独立实现参考函数，在方案中记录实现依据与验证方式；不得以被测 kernel 自身输出作为预期值。

## 产物

在本轮方案中列出：规格→case ID 的覆盖矩阵、golden/参考实现的来源与版本、逐输出 checker/阈值的实际取值和权威源、测试命令及测试入口。测试工程将其物化为 `scripts/cases.yaml` 与必要测试脚本，按 [测试框架](test-framework.md) 的格式与入口执行。

覆盖矩阵逐维标注命中用例编号，无「任意/不限」式开放上界，无未命中维度（补充用例列填「—」）。约束逐条覆盖：正常用例在边界取值、L2 用例单独触发各 constraint 违反（干净命中——前置约束全过，仅目标约束违反）。

## 精度口径

逐输出张量记录 dtype、判定指标、阈值、权威源、实际 checker 位置。整型→逐字节精确（`np.array_equal`，atol=0/rtol=0）；浮点→`np.isclose`（按 spec 阈值）。口径一致性声明：本地判定与权威源逐项一致，无差异、无放宽。详见 [精度口径](precision.md)。
