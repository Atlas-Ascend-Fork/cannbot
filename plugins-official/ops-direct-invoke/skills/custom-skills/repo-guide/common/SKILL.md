# 通用仓库指南

先读目标仓的 AGENTS.md、贡献规范、构建说明及与本任务相关的已有算子/测试，记录实际路径与版本。已有工程沿用其接口、目录、测试入口、许可与格式；资料冲突时说明依据，不把示例当成新强制标准。

- 明确代码、测试、规格、独立 Golden、结果与文档的位置，区分只读参考仓和授权交付目录。
- 测试先验证用例能发现、参数能绑定、Golden 可调用、错误输出会失败，再运行任务要求的完整集合。尚无 kernel 时的框架自检不算设备通过。
- 黑盒从确认规格覆盖接口、shape/dtype、数值、边界和异常；白盒从当前源码分支补充用例，复用已有用例与执行器，记录需求/分支到 case ID 的对应。
- 沿用仓库的真实 checker 与生效阈值，Golden 独立于候选。正常功能、预期异常、跳过和未执行分开统计，不用宽松近似 checker 取代原判定。
- 检视候选实际计算路径、设备/stream、资源与同步、边界、导出接口及构建/加载版本；不得用预置答案、CPU 回退或外部代算冒充要求的设备实现。
- 保留原始命令、退出码、逐例结果和版本映射；算子源码变化后补齐受影响回归，最终全量证据必须对应交付版本。验收者审查证据，不代替执行者补跑。

仓内无框架时，依据已选 `ops-direct-invoke-engineering` 的配套模板建立最小测试入口，写明精度依据和执行范围。无可核对的规格或入口时报告具体缺口；本 Skill 不保证任意仓开箱可用，也不默认生成 CANN Bench 布局。
