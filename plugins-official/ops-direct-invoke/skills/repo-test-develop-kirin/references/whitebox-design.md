# 白盒用例接入（直调工程）

从当前 kernel、Tiling 和 dispatch 源码出发，记录有效分支的文件、函数、条件与版本。覆盖尾核/尾块、对齐、dtype、UB 边界、分派路径及适用的 tilingkey。知识搜集草稿不约束实际分支——以源码实际控制流为准。

## 流程

1. 逐文件/函数/行号枚举 kernel 计算分支与 host 校验分支，给每个分支编号（如 B-DISP-2/3、B-RINT-3a/3b、B-VLD-C6）。对每个分支反推需求范围内的输入，采用阈值两侧、整除/非整除、边界值等代表参数；已有黑盒命中时复用 ID，不为凑数量重复造例。
2. 把新增正常用例写入同一 `scripts/cases.yaml`，使用未占用的整数 ID（从首个未占用 case_id 起），在 `note` 和阶段覆盖记录中注明源码条件（分支编号、文件:行号、触发参数）。沿用原 golden 与 checker，不另建数据生成/比对框架。
3. 需求定义的异常或无法由 YAML 表达的输入按 [测试框架](test-framework.md) 接入补充测试（如 host 参数校验的 validation 用例）；必须进入统一回归清单，不只提交设计文档。
4. 运行当前任务要求的黑盒与白盒（全量），记录实际执行数、结果和证据。区分源码推导可覆盖、执行中实际命中和因缺陷受阻——不能把推导当实测覆盖。

## 接入质量

- 白盒用例必须**实际命中**目标分支：simulator 用例逐字节通过（byte-exact）；validation 用例正确拒绝（返回预期 error_code）。验收者独立复算确认触发条件，不只信任设计文档声明。
- 干净命中：validation 用例的前置约束全部通过，仅目标约束违反（如 C6 违反时 C1-C5 全过），避免多约束同时违反导致归属不清。
- 分支覆盖记录逐分支标注命中用例编号与命中数；error_code 覆盖矩阵记录已覆盖/未覆盖（spec 排除的约束合理不测）。

## 缺陷归属

测试或接入错误由测试工作修复；正确用例暴露的算子缺陷（kernel FAIL）时记录失败 ID、复现命令和证据，保留用例及失败结果交下游代码修复，不在此节点改算子。源码修改后复核受影响分支与用例映射，最终交付必须通过全量回归。

测试文件是目标仓交付件（`operators/<op>/scripts/`）；分支映射和运行报告按本节点 ID 写入 `$WORK_DIR`。不修改被测算子、golden、阈值或校验器以掩盖失败。
