# 算子代码审查补充清单

以下只列相对现有 `ascendc-code-review` 和本工作流四项一致性检查的补充内容；部分条目仅取未覆盖的子项。

## 使用与记录

- 在现有 code-review 节点内逐项检查。输入包括算子源码、规格与设计、实际使用的 Golden/适配插件，以及已提供的兼容性基线；沿真实调用链读取依赖。目标平台和交付范围取当前工作流的规格与架构记录。
- 在 `CODE_REVIEW.md` 增加覆盖表：`检查 ID | PASS / FAIL / SUSPICIOUS / N/A | 证据或原因 | 关联发现 ID`。确认缺陷使用现有 F 编号，证据不足使用 S 编号；不适用须说明条件。相同缺陷关联同一发现，不重复报告；仅完成静态检查不代表上板通过。
- 保留现有规则的判空、输入合法性、整数安全、特殊值、资源释放、同步配对、硬件参数和 VF 检查；本清单不重复这些条款。文档格式、样例及声明一致性继续由已有文档生成与一致性检查负责。
- Golden 继续遵守当前生成契约：保留 T1/T2/T3（含 NumPy 回退）；Torch E2E 保留其本地 Golden 及清除 third_party 的约定。GM 搬运继续使用现有规则。
- 有实际支持声明才展开框架通路；尚未到本阶段交付的产物不作为缺件。兼容性条目仅适用于有兼容承诺的迁移或增量开发；需要但未提供的基线记为证据不足，新算子无兼容承诺时记 N/A。检查读取已有源码与证据，不新增设备测试或专用收据要求。
- 修复沿用现有 fix-findings 白名单。Golden、规格、测试或外部依赖中的问题保留发现与责任归属，未解决的 FAIL 仍保持打开；不通过修改冻结参考、用例或容差消除发现。

## Host 与 Kernel 数据及计算契约

| ID | 补充检查 |
|---|---|
| CODE.07 | 对照 Host 写入与 Kernel 读取的 TilingData，核对字段顺序、宽度、符号性、序列化大小和分支解释，确认两侧使用同一数据契约。 |
| CODE.08 | 将 Host 生成的 TilingKey 与模板实例、Kernel 派发分支逐一对应，确认合法输入不会落入未实现分支；检查实际映射，不重复已有宏写法规则。 |
| CODE.09 | 推导各核及尾块的输出区间，检查合法小输入、空工作块下是否漏算、重算或遗漏输出；归约、原子操作允许的重叠按其语义判断。 |
| CODE.10 | 沿 Host 的默认值填充、归一化、维度变换到 Kernel 消费核对数学语义；对会共同影响同一参数或输出的模式开关，使用合法小规模见证检查组合优先级及输出映射。 |
| CODE.11 | 核对实际浮点计算链中的近值相减、量级悬殊和先溢出/下溢再缩放；按实际舍入后的中间值及补偿分支判断是否违反既定精度要求，不能只凭数学等价或使用 FP32 判正确。 |
| CODE.13 | 追踪非连续输入的适配与输出回写：区分原对象和临时连续副本，确认结果回到调用者可见的对象或视图，并满足别名及原地语义；不强求 Kernel 原生支持任意 stride。 |
| CODE.15 | 对用户 Workspace 各段追踪全量 shape 因子与分块因子；检查是否存在钳制、搜索预算或带替代回退的总量门控，记录无上界增长风险，不能以已有非零 Workspace 赋值代替。 |
| CODE.17 | 对使用真实 TILING_KEY / TILING_KEY_IS 宏的自由内联函数检查 static 内部链接；区分同名变量、成员函数和 Kernel 入口，不机械给依赖实例状态的成员函数加 static，也不豁免现有宏禁用规则。 |

## 队列容量与入队契约

| ID | 补充检查 |
|---|---|
| TQUE.01 | 按同一 TPosition 分别汇总同时存活 Tensor、Buffer 和事件峰值，与目标平台的对应上限比较；双缓冲按两块 Buffer 计算，不把队列个数当 Buffer 数。 |
| TQUE.02 | 区分队列 depth、InitBuffer num 与连续 EnQue 需求；核对 non-inplace 返回新 Tensor、inplace 传入 Tensor 的接口约定，不能把双缓冲机械等同于 depth=2。 |

## 图注册与推导

| ID | 补充检查 |
|---|---|
| GEIR.04 | 逐输出核对 shape 方程、未知 Rank 与未知轴的传播、零长度维及 ValueDepend 语义；检查未知维标记经过转换后是否保持含义，不以 Tiling 对具体形状的处理代替图推导。 |
| GEIR.05 | 逐输出核对 dtype 推导随输入组合、属性变化的规则，区分中间计算类型与公开输出类型，不以注册支持集合代替推导结果。 |
| GEIR.06 | 核对动态 Shape/Rank、属性和 ValueDepend 是否参与编译或缓存身份，防止不同语义复用同一计划；仅据可见实现下结论，实际复用效果仍需运行证据。 |
| GEIR.08 | 适用静态二进制交付时，对照 binary JSON 与原型属性的名称集合、顺序及 SoC 归属；集合差异与纯顺序差异分别说明，静态契约差异不直接等同编译失败。 |
| GEIR.10 | 按实际 dtype/format 定义核对产品支持集合属于 REG_OP 原型范围；允许原型更宽，不要求两者相等，也不把参数列表展开为未承诺的笛卡尔积。 |
| GEIR.12 | 有融合 Pass 时，核对有中间量丢失风险或训练/推理语义差异的 runmode 门控、pattern 匹配优先级、InferShape 的 GE 版本条件及 attr 到 input slot 的替换映射；纯逐元素等价替换不强制区分 runmode。 |

## 公开接口与框架适配

| ID | 补充检查 |
|---|---|
| ROUTE.04 | 沿 Workspace 查询、实际分配到执行核对 Executor 与其参数的绑定及重复使用边界；资源有效期覆盖异步完成，不要求所有框架暴露 ACLNN Executor。 |
| ROUTE.07 | 对声明支持的 Torch eager 入口分别追踪 op-plugin 或 torch extension 到 ACLNN 的实际绑定；自动生成映射核对源 YAML 规则，不因没有手写 wrapper 判缺失，也不以同名接口证明映射一致。 |
| ROUTE.08 | 对已有且声明支持的 TF 通路追踪前端节点、转换和最终实现，核对参数与输出映射；实现可来自版本匹配的框架依赖，遵守本工作流 TF 阶段的适用性结论，不由名称猜支持或替换其 N/A 判定。 |
| ROUTE.09 | 对声明支持的 Torch 图通路，分别核对 schema、Meta、PrivateUse1、op→GE 转换及 GE→ACLNN 下沉的契约；逐入口记录支持组合，声明差异与已验证的运行失败分开。 |
| ROUTE.16 | 核对 ACLNN 前后插入的 Cast 是否承担接口、布局、ABI 或精度责任；仅在原 dtype 已被 Kernel 和注册支持且转换无必要时报告冗余，特别追踪先降精度计算再升精度输出的路径。 |

## Golden 与比较完整性

| ID | 补充检查 |
|---|---|
| GOLDEN.03 | 按实际入口核对 Golden 收到的 Tensor、Scalar、Optional、TensorList 容器及布局转换，确认适配保持数据语义；一个入口成功不证明其他入口的容器契约正确。 |
| GOLDEN.08 | 对照实际输出数量、顺序、嵌套容器、dtype 和 shape，核对 Golden 返回结构及允许的输入修改；多输出或原地接口不能只比较首个返回 Tensor。 |
| GOLDEN.10 | 核对参考实现中的随机性、全局状态和有效输入域；参考自身不稳定或不适用的范围单列，不能归为算子确定性失败。 |
| GOLDEN.14 | 除注册存在外，核对目标 Loader 的发现规则、同 key 覆盖顺序、继承/None 属性及模块初始化，确认实际选中的文件和类属于当前交付；静态推断不冒充加载成功。 |
| GOLDEN.15 | 检查 pre_compare / compare 及默认比较结果是否完整覆盖各输出；关注排序、裁剪、zip 截断、空列表、None/SUPPRESSED 和模式哨兵造成的漏比较。需要输入上下文时核对 compare_context 的真实传递契约，汇总 PASS 不替代逐输出结论。 |

## 有兼容承诺时的基线对照

| ID | 补充检查 |
|---|---|
| COMPAT.01 | 确认基线与目标的算子身份、版本及产品范围，比较输入输出角色、Optional/动态数量、属性默认值与公开约束；区分能力扩展、损失和语义变化，同名不是身份依据。 |
| COMPAT.02 | 沿两侧实际 InferShape/InferDataType/Verify 入口比较基线合法输入的接受条件和输出推导；不能将基线漏校验的非法输入当支持能力，也不因内部错误码不同直接判不兼容。 |
| COMPAT.03 | 对照基线合法域内的 Tiling 分支可达性和能力上限，举证新增拒绝或能力损失；不同芯片不要求分块策略、核数、TilingKey 或数据布局相同。 |
| COMPAT.04 | 还原基线 INI 与目标 OpDef 的按位置支持组合、属性、动态能力和实际 AddConfig 继承，区分历史基线比较与同仓产品比较；未声明某产品不要求为比较补注册。 |
| COMPAT.05 | 沿构建配置、注册回调追到最终 Tiling 实现，核对迁移后是否误用旧实现；旧宏或共用 helper 的存在不等于串路，必须给出实际派发证据。 |
