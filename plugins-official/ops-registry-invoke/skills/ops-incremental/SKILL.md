技能资源按 skill 名称定位，读取前从实际加载的目标 SKILL.md 所在目录解析为绝对路径。
`$WORK_DIR` 为本次 work_dir 的绝对路径。

## 流程

1. **需求分析。** 保留用户原始需求、验收条件与授权；定位目标算子和工程位置。
   确认这是已有算子的有界增量：不改变公开接口与既有数值语义，改动不超出
   目标算子包。全量回归必须通过，性能不得劣化。缺失信息只澄清必要的部分。
2. **选择工作流模块。** 通读 ops-registry-invoke skill 的 workflows 目录下已有
   工作流模块（如 op-design、op-impl、op-update、performance-optimization、
   code-review、doc-gen、requirements-spec、env-setup），按本次需求和模块适用
   范围挑选可复用的任务。能复用的必须复用；只有真实缺口才新建通用任务，
   并写明为何无法复用。按模块的输入、验收与授权约定适配当前工程和依赖，
   按实际执行目录解析输入与产物路径；缺项保留为执行前置条件。
3. **生成 workflow.yaml。** 把通用任务与所选模块任务实例化并连成有向无环图：
   每个任务写清目标、验收、依赖与重试，测试先行。把新增验收条件的依据核对
   纳入分析任务的验收，放在基线冻结与实现之前：逐项引用原始需求或既有接口
   约定；有前提的要求须确认前提成立。按 workflow-orchestrator 的公开说明检查
   生成图。yaml 写入 `$WORK_DIR/workflow.yaml`，是本次专属产物；任务结束后归档，
   下一项需求重新生成。
4. **交给 workflow-orchestrator。** 在本次运行目录用 workflow-orchestrator 执行
   生成的 yaml：编排器的任务状态与证据（`$WORK_DIR/.workflow/`、日志）必须落在该目录。
   原样交接用户 prompt、work_dir 与 provider，跟踪运行至完成，交付结果与
   未完成项。不得绕过编排器自行执行任务，也不得只在临时目录演练 yaml 后
   代替执行。plan-only 时生成并检查 yaml 后停止，并明确说明未执行。

## 通用任务

一次增量工作流通常由以下通用任务构成；生成 yaml 时按本次需求实例化、裁剪
或补充，能对应到工作流模块的优先复用模块任务。分析类任务以**核对为目标**
而非穷举：范围限于本次增量触及的交付件与直接依赖，逐项核对即止，不做全包
或全库扫描，不复述与本次增量无关的实现；需要什么查什么，查到即收。

所选模块已承担的设计、实现和验证不重复安排；验收覆盖不得删减，已有证据
按模块约定复用，仅对缺失或失效部分补验。

- **现状分析**：针对目标能力核对其缺失与可复用项，产出可核对的现状结论
  与复用依据；“已有支持”按 ops-registry-invoke skill 的 workflows 目录中
  `op-update.yaml` 的分析验收核对，禁止扩展为全量盘点。
- **基线构建**：在改前状态完成构建并运行既有测试，记录基线结果，作为
  delta 测试和后续全量回归的对照。
- **涉及交付件分析**：确定本次变更影响的交付件（实现、测试、文档、构建
  配置等）与有界改动范围，明确不改动项及其理由。
- **增量需求实现设计**：给出满足需求的最小改动设计、各任务验收标准与
  依赖顺序，声明对既有行为的预期变化与不变量。
- **delta 测试**：按原始需求验收；有明确失败判据的缺口先验证改前失败、
  改后通过，已有支持保留覆盖目标入口和条件的通过结果作为回归。相对改善
  与改前基线同口径比较，不另造阈值。用例失败先核实原因，不能以设施错误
  或改验收口径制造通过/失败。
- **实现**：最小改动使 delta 测试与相关既有测试 GREEN，不引入无关变更。
- **全量回归**：运行全量测试与性能对照，回归不通过或性能劣化即失败。
- **评审与修复**：对改动做独立评审，发现问题回到对应任务修复后重跑验收。
- **文档校验**：核对受影响文档与实际行为一致，文档与代码不一致不得通过。
- **交付**：按既有授权提交、推送并创建 PR，改动不得超出已分析的交付件范围。
  交付前核对最后一次修复后的产物与有效验收证据一致。

## 边界

- 不修改用户已有改动；规划期间源码只读。
- 独立验证失败或运行中断时保存现场、报告并结束本次调用，不自动恢复或另起运行。
- 结构校验和 dry-run 不等于功能验证通过；提交、推送和 PR/Issue 按既有用户授权处理。
