# Common SIMT Compile Errors

Quick reference for SIMT compilation errors. Rows marked **[V]** were reproduced and fixed on-device against CANN 9.1.0-beta.3; the rest are historical.

**Related**: [simt_build_and_compile.md](simt_build_and_compile.md) — Full compilation guide with detailed walkthroughs

---

## Error Table

| Error pattern | Likely cause | Fix |
|---|---|---|
| **[V]** `use of undeclared identifier 'tilingData'` / `'td'` on the `GET_TILING_DATA(...)` line | `GET_TILING_DATA` is generated by msopgen's `tiling_data_def_build.py`; it exists in **no** CANN header | Build through the msopgen project, or add the `#ifndef GET_TILING_DATA` fallback to the tiling header — [get_tiling_data_pattern.md](get_tiling_data_pattern.md) |
| **[V]** *no error* — exit 0, but `nm -C x.o \| grep -c 'simt_'` returns 0 and there are no `Kernel_Type` markers | `--cce-aicore-only` omitted from a `-c` compile, so bisheng emitted the **host** half of the translation unit. Silent: nothing warns you | Add `--cce-aicore-only`. Gate every device compile on the `nm` symbol count, not on `$?` |
| **[V]** `fatal error: 'kernel_tpipe.h' file not found` (also `__hif8` / `__fp8e4m3 is not supported on this target`) | Wrong front end — `-x cce` on a `.asc` source. **Not** a missing include path; extra `-I` flags do not help | Use `--asc-aicore-lang` |
| **[V]** `fatal error: '{op}_custom_tiling.h' file not found` | Kernel's own tiling header not on the search path | Add `-I.` (or the directory holding it) |
| **[V]** `cannot specify -o when generating multiple output files` | `--cce-aicore-only` passed to a build that links a `main()` | Drop the flag, or add `-c` for a device-only compile |
| **[V]** `call to __host__ function from __global__ __aicore__ function` at `Init{Struct}` | `__NPU_TILING__` not defined, so the host overload is the only candidate | Add `-D__NPU_TILING__` |
| **[V]** `ld.lld: the type of kernel function ... auto derivate failed` (preceded by `kernel type ... is not marked`) | No kernel task type on a **non-puresimt** `__global__` entry. `REGISTER_TILING_DEFAULT` alone does **not** supply one | Add `KERNEL_TASK_TYPE_DEFAULT(...)` as the first statement of the entry function. Cannot arise under `-cce-enable-puresimt` — that dialect infers AIV |
| **[V]** `undefined reference to 'exp'` / `'log'` / `'pow'` | libm not linked; fails at link so it reads as a codegen fault | Add `-lm` |
| **[V]** `__gm__` qualifier rejected inside `main()` | Device address-space qualifier used on a host pointer cast | Drop `__gm__` from host-side casts; only kernel params carry it |
| **[V]** driver error when both `-xasc` and `--asc-aicore-lang` are passed | The two front-end selectors conflict | Use `--asc-aicore-lang` alone |
| **[V]** `unknown type name '__device__'` | `__device__` is defined in **neither** compiler dialect | Mark device helpers `__simt_callee__` |
| **[V]** `simt_callee function can only be called by simt_vf/simt_callee function` | Warp intrinsic (`asc_reduce_add`, `asc_shfl_*`) called from an unqualified or `__aicore__` helper | Mark the helper `__simt_callee__`; call it only from a `__simt_vf__` |
| `Unsupported NPU architecture or soc` | Wrong `--npu-arch` value (e.g. `dav-3101`) | Use `dav-3510` for Ascend950PR. Only `dav-2002`, `dav-2201`, `dav-3510` are valid in CANN 9.1.0-beta.1 |
| **[V]** `expecting global function ... requires the __aicore__ or __aicpu__ qualifier` + `undeclared identifier 'blockIdx'` | Model A compiled in the non-puresimt dialect | Add `-cce-enable-puresimt` (Model A only; B/C must not have it) |
| `launch syntax arity mismatch` | Model A uses 4-arg, Model B uses 3-arg `<<<>>>` | Check model and use correct arity |
| `missing __global__ annotation` | Kernel function not marked as device code | Add `__global__` (Model A) or `__global__ __vector__` (Model B) |
| `asc_vf_call target is not a function` | VF is a class member | Make VF a free function |
| `asc_vf_call forward reference` | VF defined after entry function | Move VF definition above entry function |
| `__gm__ qualifier missing` | VF pointer args lack `__gm__` | Add `__gm__` to all VF pointer params |
| `warp function in __global__ __vector__` | Using `asc_shfl_*` etc. in Model B entry function | Move warp calls into VF function (Model B) or use Model A `__global__` kernel directly |
| `struct argument to asc_vf_call` | Non-primitive arg type | Pass only pointers and primitives |
| `threads_per_block not multiple of 32` | Thread count misalignment | Round up to next multiple of 32 |
| `ASCENDC_CPU_DEBUG undefined` | Missing CPU debug include | Add `#include "tikicpulib.h"` inside `#if defined(ASCENDC_CPU_DEBUG)` guard |
| `undeclared identifier asc_syncthreads` | Missing sync include | Add `#include "simt_api/device_sync_functions.h"` |
| `undeclared identifier asc_shfl_down` | Missing warp include | Add `#include "simt_api/device_warp_functions.h"` |
| `call to '__popc' is ambiguous` | `lanemask_*()` return **signed** `int32_t`, and `__popc` only has `unsigned int/long/long long` overloads, so a bare `__popc(lanemask_lt())` matches none uniquely | Cast: `__popc(static_cast<uint32_t>(lanemask_lt()))`. The documented ballot form `__popc(mask & lanemask_lt())` is **not** affected — `mask` is `uint32_t`, so the `&` promotes the result to unsigned |
| `asc_copy_gm2ub_align undeclared` | Missing SIMD include (Model B pre-staging or Model C) | Add `#include "c_api/asc_simd.h"` |
| `undeclared identifier asc_atomic_cas` | Missing atomic include | Add `#include "simt_api/device_atomic_functions.h"` |
| `undeclared identifier laneid` / `lanemask_lt` | **Not an include problem.** These are compiler intrinsics defined in `__clang_cce_simt_spr.h` (auto-included by the CCE front end), not library functions — `device_warp_functions.h` contains zero occurrences of `laneid`. Adding it will not help | Check the **front end** instead: you need `-x cce` (or `--asc-aicore-lang`) and `--npu-arch=dav-3510`. Without the CCE front end the builtin header is never pulled in |
| `undeclared identifier asc_atomic_add` on `half`/`bfloat16_t` | 16-bit atomics are in the **dtype** headers, not `device_atomic_functions.h` | Add `#include "simt_api/asc_fp16.h"` (or `asc_bf16.h`). Do not write a CAS loop — the native overload exists |
| `undeclared identifier asc_ldcg` | Missing device functions include | Add `#include "simt_api/device_functions.h"` (or `asc_simt.h` may suffice) |
| `undeclared identifier printf` in device code | Missing printf header | Add `#include "asc_printf.h"` |
| `volatile qualifier error` | Incorrect volatile usage in spin-wait | Use `*reinterpret_cast<volatile uint32_t*>(&var)` pattern |
| `undeclared identifier __cvt_int32_t` | Missing include for cast intrinsics | Ensure `#include "simt_api/asc_simt.h"` is present |
| `undeclared identifier ROUND` | Missing ROUND enum | Auto-included via `asc_simt.h`; check `--npu-arch=dav-3510` is set |
| `undeclared identifier __ldg` / `__stg` | Missing include for load/store intrinsics | Ensure `#include "simt_api/asc_simt.h"` is present |
| `undeclared identifier KERNEL_TASK_TYPE_DEFAULT` / `KERNEL_TYPE_AIV_ONLY` | Under **non-puresimt** (Model B/C): missing `kernel_operator.h`. Under `-cce-enable-puresimt` (Model A): the macro is unreachable in that dialect, not merely un-included | Model B/C → add `#include "kernel_operator.h"`. Model A → **delete the macro**; adding the include only moves the failure into the header ([simt_build_and_compile.md §2.3](simt_build_and_compile.md#kernel-task-type)) |
| `aclrtLaunchKernel undeclared` | Invented launch API | No host launch API exists. Use `k<<<blocks, l2ctrl, stream>>>(args)` syntax |
| device-pass errors in host code | Missing TU guard | Wrap host section in `#ifndef __CCE_AICORE__` (Model B) or `#if defined(ASCENDC_CPU_DEBUG)` |
| `undeclared identifier gridDim` | Missing SIMT include in Model A | Add `#include "simt_api/asc_simt.h"` |
| `error code = 334: BIU→VEC data error, subErrType: 0x4` | SIMT thread wrote to OPP workspace buffer | Do NOT use workspace for SIMT-writable memory. Use input/output tensor tails or dedicated scratch tensor. Set `workspace[0] = 0` in TilingFunc |
| `Cannot select: i64 = ctpop` | ctz/popcount builtins not instruction-selectable on ascend950 bisheng | Remove; use shift-loop instead |
| 507035 on int64 `tile[32][32]` = 8192 B | **Contested — not a confirmed static-UB ceiling.** The same tile passes bit-exact on another part, so the 8192 B boundary may not be the cause. Static `__ubuf__` a VF declares itself is not bounded by the 8 KB pointer-passed window | Shrink to TILE=16 (`tile[16][17]` = 2176 B) — safe on every part measured. See `memory_optimization_guide.md` §9 |
| `asc_vf_call` wrapped in helper template fails to compile | `template<auto>` NTTP cannot be re-wrapped in another template | Emit `asc_vf_call<...>` only where dtype/rank is concrete (macro inside each dtype `case`) |
| `error: initialization is not supported for __shared__ variables` on a `__ubuf__ T* p = ...` line | A `__ubuf__`-qualified **pointer** cannot carry an initialiser — the qualifier is a `__shared__`-class attribute. Applies to pointers *into* UB, not just UB arrays | Split declaration from assignment: `__ubuf__ T* p; p = base + off;` — or drop the pointer and index the array directly (`base[off + i]`). Both device-verified; see `simt_advanced_patterns.md` §1.12 |
| `error: __constant__, __device__, and __managed__ are not allowed on non-static local variables`, pointing at a **kernel parameter** | `__gm__` written on a Model A param. Under `-cce-enable-puresimt` the macro is `__attribute__((device))`, invalid there | Drop `__gm__` — Model A takes plain `T*`. Keep `__gm__` only on Model B/C VF params |
| EZ1001 at benchsite bundle build; local compile succeeds | VF calls a device helper function; benchsite AOT (9.1.0) silently drops such VFs | Inline all helper logic into VF; VFs must be fully self-contained (no device helper calls) |
