# Gather — Model B, 20/20 Cannbench Verified

> **Model**: SIMT VF (Model B) — `__simt_vf__` + `__aicore__` entry with `asc_vf_call`
> **Verified**: 20/20 cannbench, Ascend 950PR (round3). Score: 58.50/100.
> **Key APIs**: `asc_vf_call`, `dim3`, grid-stride loop, immutable tiling pointer
> **Dtypes**: float32, float16, bfloat16, int8, int32, int64 × {int32, int64} index

## ⚠️ Which gather this is

This implements **`torch.gather`** semantics — equivalently ONNX **`GatherElements`**:

- `index` shape **==** output shape — **one index per output element**
- the kernel reads `index[idx]` where `idx` is the linear *output* position
- `InferShape` sets `y_shape = index_shape`

It is **not** axis-gather. If your operator is `np.take` / `torch.index_select` /
ONNX `Gather` / TF `GatherV2` — where `index` is 1-D and selects whole *slices*
along an axis — **this kernel is the wrong semantics** and will produce wrong
values while compiling and running cleanly.

The two are a well-known silent-bug pair; see
[`simt_operator_patterns.md`](../../simt_operator_patterns.md)
§"Irregular Indexing — `torch.gather` vs `index_select`" before adapting this.
For axis-gather you need `index[coord_along_dim]`, not `index[idx]`, and an
output shape built from the input shape with `dim` replaced.

**Copy the structure, not the indexing.** Grid-stride, immutable tiling pointer,
coord decomposition, and multi-dtype dispatch are reusable for any Model B
operator. The `index[idx]` read on line 41 is specific to `torch.gather`.

## Building

This is an **msopgen project kernel**, not a standalone `.asc`. It uses
`GET_TILING_DATA`, generated by msopgen and present in no CANN header, so
compiling it directly gives `error: use of undeclared identifier 'td'` —
expected, not a defect. Build through its project, or use the shim +
`-D__NPU_TILING__` recipe in
[`simt_build_and_compile.md`](../../simt_build_and_compile.md) §2.4.

`KERNEL_TASK_TYPE_DEFAULT(KERNEL_TYPE_AIV_ONLY);` at the top of the entry
function is mandatory and is not implied by `REGISTER_TILING_DEFAULT`.

## Key Structural Patterns

### 1. Grid-stride loop (SKILL.md rule 8)
The VF iterates `for (idx = tid; idx < total; idx += gridDim.x * blockDim.x)` — not `if (tid >= N) return`. This allows a bounded grid (`numBlocks` capped at host) to cover any output size.

### 2. Immutable tiling pointer (SKILL.md rule 12)
The entry passes `__gm__ const GatherCustomTilingData* tg` directly to the VF. The VF reads shape/stride arrays from this immutable GM buffer — no mutable `__gm__` globals, no cold-launch race.

### 3. N-D coord decomposition (general dim)
Output index → N-D coords via modular decomposition, then coord[dim] replaced by the gathered index → input offset via strides. Works for any dim, not just dim=0.

### 4. Multi-dtype dispatch macro
The entry uses a `#define GATHER_DISPATCH(T)` macro that expands the index-dtype if/else inline, keeping the dtype switch compact (6 dtypes × 2 index dtypes = 12 instantiations in ~10 lines).

### 5. `dim3(td.threadsPerBlock)` not `dim3(totalBlocks)` (SKILL.md rule 11)
The `dim3` arg to `asc_vf_call` is the per-block thread count (256), not the grid size. The grid is set via `SetBlockDim(numBlocks)` on the host.

### 6. Tiling struct with inline arrays
Shape, stride, and input-shape arrays are `uint32_t[8]` inline in the tiling struct — no device pointers, no dynamic allocation. Filled by `TilingFunc` from `GetInputShape`.

## Host (TilingFunc) Patterns

- Every kernel-read field set from runtime shapes/attrs (SKILL.md rule 6)
- `dim` attribute normalized: `if (dim < 0) dim += ndim`
- `numBlocks` capped: `min(ceil(total/256), 32768)` + `SetBlockDim`
- `workspace[0] = 0` (SIMT: no OPP workspace)
- `dtypeCode` from `GetInputDesc(0)->GetDataType()` (not `GetInputDataType`)
